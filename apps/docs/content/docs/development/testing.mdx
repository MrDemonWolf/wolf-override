**What this page is for:** run the checks before you open a pull request, and know what CI runs.

- **What the checks have proved so far** is on [What was checked](/docs/development/evidence/).
- **Debug overlay, cheats and bug captures** are on [Debug tools](/docs/development/debug-tools/).

## Run the checks

From the repository root, in this order:

1. `bun run game:check`: the Godot import, then every headless test suite.
2. `bun run check:copies`: no new copied code since `origin/main`.
3. `bun run docs:check`: MDX and Next types, then TypeScript.
4. `bun run docs:test`: the docs unit tests.
5. `bun run docs:build`: the static site, then the export checks.

<Callout type="warn" title="A pass proves logic, not feel">
  Headless suites do not show how a route feels, reads or sounds. If your change touches movement, pacing, readability or WOLF, also play the route and say what you played. See [Project rules](/docs/development/rules/).
</Callout>

## Game checks

`bun run game:check` runs `scripts/check-game.sh`.

- **Import:** Godot imports the project twice. The first pass may report only the known font errors of a fresh checkout; the second must be error-free.
- **Suites:** then every `apps/game/tests/*_test.gd` suite runs, up to four at a time.
- **Your saves are safe:** each suite gets its own temporary user data folder, so it never touches your saves or editor settings.
- **English always:** every suite starts with `--language en`, whatever language your computer uses.
- **Fixed frame rate:** `opening_timing_test` and `opening_early_press_test` start with `--fixed-fps 60`, so every frame is 1/60 s of game time even on a busy machine. They fail without it.
- **A suite fails** if it reports an error, leaks objects at exit, or is still running after 240 seconds.
- **Leaks:** a leaking suite runs once more with verbose output, so its log names the leaked objects.
- **Hung:** a suite still running at the limit is stopped and reported as hung. Each import pass has the same limit.
- **The translation template:** `i18n_test` and `companion_rules_test` read the committed `i18n/messages.pot` (its story and speaker marks). After changing player text, regenerate it before running them. See [Localization](/docs/development/localization/#commands).
- **macOS:** works without GNU `timeout`.
- **Logs** are kept, and their folder printed, only when a check fails.

Run one suite on its own:

```sh
godot --headless --language en --path apps/game --script res://tests/<name>_test.gd
```

For the two opening suites, add `--fixed-fps 60` after `--headless`.

| Setting | What it does |
| --- | --- |
| `GODOT_BIN` | The Godot binary, if `godot` is not on your path |
| `CHECK_JOBS=1` | Run the suites one at a time |
| `SUITE_TIMEOUT` | Seconds before a suite counts as hung (default 240) |
| `CHECK_LOG_DIR` | Keep every log in this folder (CI uses it) |

- **Skip the logo screen:** the game starts on the MrDemonWolf, Inc. logo, then the title. A normal launch can pass `-- --skip-logo`, for example `godot --path apps/game -- --skip-logo`. A headless run always skips it, and suites that load `scenes/main.tscn` directly are unaffected.
- **What each suite checks:** [What the headless suites cover](/docs/development/evidence/#what-the-headless-suites-cover).

## In-game changelog

The same script keeps the in-game changelog in step with the website.

1. Edit `apps/docs/content/docs/changelog.mdx` (add lines under **Next version**).
2. Run `python3 scripts/export_changelog.py` (Python 3, standard library only).
3. Commit the regenerated `apps/game/assets/changelog.txt` in the same pull request.

- **The check fails** when the committed text differs from what the script writes.
- **Export presets:** the file is a plain `.txt`, which Godot does not pack by default. The presets in `apps/game/export_presets.cfg` include it, and the two font licences, by name. A new preset must too, or the in-game screen shows its "missing from this build" line.
- **Versions:** see [Releases and versions](/docs/development/releases/).

## Copied-code check

`bun run check:copies` runs `python3 scripts/check-copies.py --base origin/main`. This is the one place it is explained; `CONTRIBUTING.md` links here.

- **What it reads:** the tracked code files from Git: GDScript, shaders, TypeScript, JavaScript, CSS, Python and shell.
- **What fails:** a run of six or more matching lines that your branch adds or touches since it left `main`.
- **What it ignores:** comments, blank lines, indentation and spaces. Spaces inside quoted strings still count.
- **Older copies on `main`** do not fail it, unless your branch edits inside one of them and six or more lines still match. That would make the copies drift apart.
- **Text, not meaning:** a copy with renamed variables passes. A pass is not proof there are no copies, and reviewers still read for them.
- **When it fails** it names both places. Move that code into one shared file that both use, and delete the copy.
- **Must stay separate?** List the pair in `.copies-allow` at the repository root, with a reason, and say why in the pull request.
- **CI:** every pull request runs it in the Game checks workflow, before Godot is downloaded.

| Command | What it does |
| --- | --- |
| `python3 scripts/check-copies.py --report` | Lists every older copy already on `main` |
| `python3 scripts/check-copies.py --self-test` | Checks the tool itself on planted copies |

## Docs checks

`bun run docs:build` builds the static site, then `scripts/check-docs-export.sh` checks the export:

- No page uses the image optimiser GitHub Pages lacks.
- Each page has its skip-link target and at most one robots tag.
- Each page limits the referrer sent to other sites to this site's origin.
- Each page carries the site's Content Security Policy, a list of where it may load files from, as a meta tag.
- Internal links and heading links point to files and IDs in the export; external sites are not checked.
- Every font is WOFF2.
- `robots.txt` names the sitemap, and every guide page in the sitemap has its last-changed date.
- The landing and guide pages carry valid structured data.
- `llms.txt`, `llms-full.txt` and every guide page's Markdown copy exist, with no raw component tags outside code blocks.

## Check a website deployment

1. Open the **Deploy Docs** run for the merged commit and confirm both build and deploy passed.
2. Open the website and check the footer's **built from** link names that commit.
3. Try the homepage, guide search, phone menu and a missing page's return links.
4. Check the press kit download, sitemap and any published GitHub Release links.

- **A build pass is not a live check.** Record which browser and screen sizes you tried.
- **A punycode warning** (`DEP0040`) in the deploy step's log is known and harmless. It comes from GitHub's deploy action, not the site.
- **No published releases yet:** test-build artifacts need a GitHub account and expire; they are not release downloads.

## Recover a broken website deployment

1. Find the last working deployment and the pull request that introduced the problem.
2. Open a revert pull request for that change; preserve unrelated work and run the docs checks.
3. Merge the reviewed revert and wait for **Deploy Docs** to finish.
4. Repeat [Check a website deployment](#check-a-website-deployment).

- **Re-running the broken commit** deploys the same broken content.
- **A website revert** does not change game downloads or subscriber data.

## Continuous integration

| Workflow | When | What it runs |
| --- | --- | --- |
| **Game checks**, `godot` job | Every pull request and push to main; manual runs too | Copied-code check, checksum-verified Godot 4.7.2 (`scripts/get-godot.sh`), `scripts/check-game.sh`, then a fresh translation template that must match `i18n/messages.pot` |
| **Game checks**, `tools` job | Same | Shellcheck, the self-tests of the copy check, `render.sh` and `compare.py`, then the translation gates. Needs no Godot |
| **Deploy Docs**, `build` job | Every pull request and push to main | `docs:check`, `docs:test`, `docs:build` |
| **Deploy Docs**, deploy | Main-branch docs changes | Deploys the site to GitHub Pages, one deployment at a time, in push order |
| **Test builds** | Beside the checks | macOS and Windows debug exports. Not a required check. See [Releases and versions](/docs/development/releases/#test-builds) |

- **Required to merge:** the `godot` check and the `build` check.
- **Template after a failure:** the translation template step still runs when a suite fails, as long as the import was clean.
- **Time limits:** the game check step has a 15-minute limit on top of each suite's own. Build and deployment jobs have limits too.
- **Failed logs:** failing or cancelled check logs are kept as downloadable artifacts for seven days. Log pipelines keep the command's failure status.
- **Newer pushes:** a newer push to a pull request cancels that pull request's older runs. Every push to main runs in full.

<Callout title="A green run is not a finished game">
  Graphical route play, hardware input, opening an export on its system, signing and physical devices are separate gates. A green workflow does not certify a finished game or release package.
</Callout>
