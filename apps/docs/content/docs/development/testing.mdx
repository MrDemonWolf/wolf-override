## Run the checks

From the repository root:

```sh
bun run game:check
bun run check:copies
bun run docs:check
bun run docs:test
bun run docs:build
```

`bun run game:check` runs the Godot import twice and then every `apps/game/tests/*_test.gd` suite, up to four at a time, each with its own temporary user data folder, so it never touches your own saves or editor settings. The first import may report only the known font errors of a fresh checkout and the second must be error-free. A suite fails if it reports an error, leaks objects at exit (it is then run once more with verbose output, so its log names them) or is still running after 240 seconds, when it is stopped and reported as hung; each import pass has the same limit. This works on macOS without GNU `timeout`. Every suite is started with `--language en`, so it runs in English whatever language the computer is set to; run a single suite the same way: `godot --headless --language en --path apps/game --script res://tests/<name>_test.gd`. Set `GODOT_BIN` if `godot` is not on your path, `CHECK_JOBS=1` to run the suites one at a time, or `SUITE_TIMEOUT` to change the limit. Logs are kept, and their folder printed, only when a check fails.

The same script keeps the in-game changelog in step with this website: it regenerates `apps/game/assets/changelog.txt` from `apps/docs/content/docs/changelog.mdx` with `python3 scripts/export_changelog.py` (Python 3, standard library only) and fails when the committed text differs. After editing the changelog, run that script and commit the result with the docs change. The file is a plain `.txt`, which Godot does not pack by default: the export presets in `apps/game/export_presets.cfg` include it (and the two font licences) by name, and any new preset must too, or the in-game screen shows its "missing from this build" line.

`bun run check:copies` keeps the code free of copies. It runs `python3 scripts/check-copies.py --base origin/main`, which reads the tracked code files (GDScript, shaders, TypeScript, JavaScript, CSS, Python and shell) from Git and fails on any run of six or more matching lines, after dropping comments, blank lines, indentation and spaces (spaces inside quoted strings still count), that the branch adds or touches since it left `main`. Copies already on `main` do not fail it unless the branch edits inside one of their places and six or more lines still match, because that makes the copies drift apart; `--report` lists them all and `--self-test` checks the tool itself. It compares text, not meaning, so a copy with renamed variables passes it: a pass is not proof that there are no copies, and reviewers still read for them. Every pull request runs it in the Game checks workflow before Godot is downloaded. When it fails, it names both places: move that code into one shared file that both use and delete the copy. A pair that truly must stay separate goes in `.copies-allow` at the repository root, with a reason.

The translation tools live in `scripts/i18n/` and need Python 3 (standard library only) and GNU gettext's `msgfmt` (`brew install gettext` on macOS). `scripts/i18n/extract_pot.sh . i18n/messages.pot <log dir>` regenerates the translation template with Godot's own generator, headlessly: it puts a small editor plugin into `apps/game/addons/` and an entry into `project.godot` for one editor run and takes both out again afterwards, so commit only the template. Run it after changing any text the player reads, and commit `i18n/messages.pot`. `python3 -I -B scripts/i18n/i18n_tool.py potfiles apps/game --check` fails when `project.godot`'s list of files to scan (`locale/translations_pot_files`) leaves out a scene or script; without `--check` it prints the line to paste. `python3 -I -B scripts/i18n/i18n_tool.py check i18n/messages.pot apps/game/i18n <report.json>` runs every gate on the translation files (placeholders, BBCode, speaker tags, line breaks, the key token, the alphabet, the glossary in `i18n/glossary.json`, the engineer never being given a gender, Slavic name endings, plural forms and their header, sibling files such as the two Chinese and two Spanish files, and comments that would make Godot skip a line) and exits 1 on any failure; `--back <file>` adds a back-translation's checks, and `--release` adds the release gates (no fuzzy line in a language marked reviewed, no untranslated line marked as story). There are no translation files yet, so today it checks nothing and passes. `python3 -I -B scripts/i18n/i18n_tool.py selftest <report.json>` runs the gates on 124 planted cases (115 for the line, plural, comment and sibling gates and 9 for the release gates) and fails if any planted error passes or any clean line fails. `python3 -I -B scripts/i18n/i18n_tool.py fonts <download folder>` rebuilds the bundled fallback fonts: it downloads the Noto Sans CJK 2.004 release files from GitHub into the folder (unless they are there), checks each font's SHA-256, cuts Noto Sans JP, KR, SC and TC down to each language's fixed common character set with HarfBuzz's `hb-subset` (`brew install harfbuzz`), writes the symbols font Roboto chains and the character lists in `apps/game/tests/support/cjk_charsets.json`, and prints the sizes. Its output is committed, so it only runs again to change a character set. The parity capture takes a language too: `scripts/parity/run.sh capture --language <code> <out dir>` plays the routes in any language of `apps/game/i18n/languages.json`, or `pseudo` for English with Godot's pseudolocalization (brackets and 30% padding), and every still's entry in `shots.json` lists the visible text that overflows its control, the characters its font cannot draw and, under `pseudo`, the text that was not translated.

## Debug tools and cheat codes

The game has debug tools for anyone testing it, so you can see what it is doing and keep a record of a problem. In a debug build (the editor, a source run with the standard Godot binary, or one of the [test builds](#test-builds)) they are always available. In any other build they stay hidden until you enter a code on the title screen:

| Input | Code |
| --- | --- |
| Keyboard | Type `WOLFDEN`, in capitals or not: Shift, Caps Lock and the other modifier keys do not break it, any other key does. |
| Controller | On the D-pad: Up, Up, Down, Down, Left, Right, Left, Right, then B (the east face button), then A (the south face button). The final A does not press the focused menu button. |
| Touch | Tap the WOLF//OVERRIDE logo mark at the top right seven times, each tap within a second of the last. |

A short **Debug tools unlocked** note confirms it. The unlock is saved with your settings, so the tools stay available on later launches until they are locked again; locking also forgets the saved unlock.

Once the tools are available:

| Input | What it does |
| --- | --- |
| **F3** | Cycles the overlay: off, performance, state, state and zones. |
| **F5**, **F6**, **F7** | On the zones page: turn the zones, the hitboxes and the render boxes on or off. The legend's buttons at the top of the screen do the same with a tap or click. |
| **LB**, **RB**, **View** (Select / Back) | The same on a controller, on the zones page: zones, hitboxes, render boxes. A button you have bound to a game action in Settings is left alone. The legend's caption names the keys, buttons or taps for the device in use. |
| **F12** | Saves a bug capture. |
| `` ` `` (backquote), both sticks pressed together (L3 + R3), or the **DEBUG** button | Opens the debug menu, or closes it when it is open. |
| **.** (period), **RB**, or the **STEP** button | While frame stepping: lets one frame of play through. |
| **Esc**, **B**, or the **RUN** button | While frame stepping: plays on at normal speed. |

- **Performance page:** frames per second, frame and process time, memory, and node, object and draw-call counts. Godot reports the game's own (static) memory only in debug builds, so in an unlocked release build that figure reads **n/a** and the page shows video memory instead.
- **State page:** the room, the current beat and objective; the engineer's position, facing and what they are doing; WOLF's position, where he is heading and why (following, scouting, holding a spot, drawing the sentry or refusing); in the Service Junction the sentry's state, position, facing, sight range and who it is fixed on, the pressure line's state, gauge, turns and fuse, the tank arm, the exit bolt and which hazards are armed; the run's relay, mirror and lane choices and WOLF's memory; the save format version, whether a checkpoint is on disk and where it stands; and whether cheats were used. The overlay keeps updating while the game is paused, and it reads the save file at most once a second.
- **Zones page (state and zones):** the state card, plus a drawing over the game that follows the camera, worked out every frame from the same shapes and constants the game's rules use, in three colour-coded layers named in a small legend at the top:
  - **Zones** (cyan), as bars in lanes under the floor line with end ticks: each station's interact range (drawn faint while it does not answer, such as the **TANK RELEASE** before the door is down), the spots the engineer steps to, WOLF's spots (with his current target and why, in white), his follow distance around the engineer and the machines he rests clear of, the sentry's lane in the Service Junction (the alcove, the patrol, its sight as an arrow from where it faces, where it watches from), and dashed lines for limits: walls, a shut door's face, how far WOLF follows, the lane entry, the sentry's chase limit and where WOLF asks about the lane. The camera's centre limits and its current position sit on the bottom edge of the screen. A range wholly off screen is listed in captures but not drawn.
  - **Hitboxes** (orange): every collision shape from its real shape (both characters, the floor, the corridor seal and the junction door while they block, the sentry's body, the relief vent and coolant cloud hurtboxes), and the rule ranges that hurt or hit: the vent and cloud by the engineer's position, the door blast (with the room above it shaded), the sentry's contact, the tank's hit range and its footprint. Anything in force right now (an armed hurtbox, a lit fuse, a falling tank) turns red.
  - **Render boxes** (yellow-green): the on-screen rectangle of every sprite, prop, plate layer, label, button and panel, and of props the game draws in code (the sentry's sight beam and lens, the bypass's crank lights and leader, room lights and beacons), with its node name, z-index and canvas layer (for example `BodySprite z2`, `PauseButton z0 L2`), so overlaps and anything drawn inside something else stand out. Boxes hidden behind the title or the end card, faded out or off screen are listed in captures but not drawn. Boxes for props drawn in code come from what the renderer recorded, which Godot reports only in editor builds; in an exported build only props that declare their area (the sentry's beam) get one, and captures say which source each box used.

  Nothing in the drawing covers the touch arrows, **USE**, the answer buttons, **PAUSE**, or the text of the hint, the dialogue, the tutorial prompt or the top card: lines, bars and fills are cut around them, and every name is placed where it overlaps none of them, no character and no other name (smaller boxes are named first; a name moved away from its box is joined to it by a short line). A name with no room left is not drawn; captures still list it, with `label_hidden`. Captures also list the protected areas under `keep_clear`. The drawing steps aside with the overlay for Pause, Settings and the game's cards, and costs nothing while another page is up.
- **The game's own screens come first:** the overlay steps aside while Pause, Settings, the END OF SLICE card or the title's Credits or Changelog is open, and in the touch layout while a question's answer buttons are up, and comes back when they close. It stays up during a question in the keyboard and controller layout, where the answers are clear of it. While the corridor's tutorial prompt is up, the state and zones pages narrow to end left of it, so its control instructions stay readable, and widen again once it has gone.
- **Bug capture:** writes a screenshot and a JSON file with the same data, plus positions and flags, to `user://debug-captures/` (Godot's user data folder for the game), named by date and time, and shows the path. A headless run writes the JSON only. The JSON's `geometry` lists every zone, hitbox and render box as numbers, whether or not they were drawn: node path, `world_rect` and `screen_rect` as `[x, y, width, height]` (screen rects in the 960×540 canvas, with the scale to window pixels beside them), z-index, canvas layer, visibility, alpha and draw order, plus the camera. Capture scripts can call `debug_tools.dump()` on the game's main node to log the same data beside their own screenshots, or `await debug_tools.capture_with_boxes()` to save a capture with every box drawn into the screenshot, whatever page is up; the tools' own note (an earlier capture's path, a jump's result) is hidden first so it is never in the picture. If the window draws no frame within ten frames (hidden or covered), that call still saves the JSON, skips the out-of-date screenshot, reports `with_boxes: false` and puts the page back.
- **DEBUG button:** in touch play a small **DEBUG** button sits at the top right, a finger's gap left of **PAUSE**, clear of the characters, **USE** and the arrows. It hides while Pause, Settings, the END OF SLICE card, Credits or Changelog is open, or a controller is in use.

### Debug menu

The debug menu holds the game still while it is open, as Pause does, and sits to the right of the overlay so the state page stays readable beside it. It uses the game's own menu card and buttons. With a keyboard or controller, focus starts on the page's tab: move along the tabs to change page (or press **LB** / **RB**), move down into the page and confirm to use a button. On touch, tap a tab or a button. **Esc**, **B**, Android Back, **CLOSE** or a tap outside the card closes it; it does not open while the game's own Pause or Settings is up. Every action notes what it did, or why it cannot, under the page. Actions that close the menu so their result plays (jumps, forced knockdowns, the fuse, the tank and reloading) leave that note for a few seconds at the top of the screen, between the top card and **PAUSE**, over nothing but the ceiling. On the zones page, whose legend has that spot, the note sits just below the answer row or under **PAUSE**, whichever covers neither character nor the Service Junction's tank. Opening the menu again clears it.

| Page | What it does |
| --- | --- |
| **JUMP** | Puts you straight at a point of the slice: the opening, the start of the corridor, WOLF's relay question, the corridor's safe point, the start of Records Access, Records Access with both copies made, the start of the Service Junction, the lane after the door blast (with WOLF already asked and answered from the **CHOICES** page), the sentry down, or the **END OF SLICE** card. Each jump builds the run through the game's own save steps from the **CHOICES** presets and loads it as Continue does. A jump to a point the game autosaves at writes that checkpoint, as play does when it gets there, replacing the save on disk; the opening, corridor start and relay question leave the save alone. |
| **CHOICES** | The earlier choices the next jump uses: how the relay went (WOLF rushed and the engineer cranked the bypass; WOLF told and taking the contact; or WOLF told and the engineer cranking anyway), who read the mirror (WOLF's readout or the manual port), and how the sentry came down (WOLF draws it, the engineer times it alone, or WOLF refuses). WOLF's lane answer follows the same rule as in play, so asking him to draw the sentry after a rushed relay turns into a refusal, and the presets change together and say so. Choosing presets is not a cheat. |
| **CHEATS** | **INVINCIBLE**: no knockdown lands; the door still blows as if the engineer were clear. **FREEZE SENTRY**: the sentry stops moving and changing state (touching one that was chasing still knocks you down unless invincible). **INSTANT CRANK**: holding interact at the junction valve or the corridor's **MANUAL BYPASS** finishes it at once through the game's own crank. **FRAME STEP**: the game holds still and a small bar near the top right lets one frame through per **STEP** (or **.** / **RB**) and plays on with **RUN** (or **Esc** / **B**); a jump or **RELOAD CHECKPOINT** while stepping keeps the game held. **SPEED**: 1x, 0.5x or 0.25x (the game's short impact pauses still dip it further for their moment). |
| **FORCE** | In the Service Junction: knocks the engineer down with the relief vent's, the door blast's, the sentry's or the coolant cloud's own card, with the same short pause, red flash and camera shake as in play, even while invincible, and the beat's checkpoint comes back as usual. **LIGHT THE DOOR FUSE** arms and cranks the pressure line so the door goes about two and a half seconds after play resumes, and where everyone stands then decides the outcome. **DROP THE TANK** lets the tank go from wherever you are; it lands on the sentry only if the sentry is over the floor brackets. Buttons that cannot work now are greyed out, with the reason below. |
| **SAVE** | Shows the checkpoint on disk. **SAVE NOW** writes the current beat through the game's own autosave (only once the first safe point is reached), **RELOAD CHECKPOINT** goes back to it, and **CLEAR SAVE** deletes it after a second press. |
| **VIEW** | **OVERLAY** steps the overlay's page (for phones, which have no F3), **BUG CAPTURE** closes the menu and saves a capture, and **VISUAL EFFECTS**, **CAMERA SHAKE** and **SCREEN FLASH** turn those off for this session (they are not cheats and are not saved). **LOCK DEBUG TOOLS** hides the tools and forgets the unlock. |

Jumps, cheats, forced knockdowns and the two triggers mark the overlay and every dump **CHEATS USED**, and the state page lists the cheats in force (for example `invincible · 0.5x`). Dumps and captures also list every cheat, preset and switch under `debug.cheats`. Locking the tools, or a build in which they become unavailable, turns every cheat off, puts the speed and the effects back and lets the game run.

While the tools are hidden, or available with the overlay off, the menu closed and no slow motion or instant crank on, they do no work each frame and draw nothing.

The tools live in `apps/game/scripts/debug/` and reach the game only through the main script's typed fields and its public `debug_*` methods (`debug_snapshot`, `debug_new_game`, `debug_load_checkpoint`, `debug_knock_down` and the like, kept together at the end of `main.gd`), never its private ones, so renaming or moving one of those fails when the scripts are parsed instead of when a menu button is pressed.

## Continuous integration

Every pull request and push to main runs a checksum-verified Godot 4.7.2 import and the scripted headless game checks through `scripts/check-game.sh`. The same job then regenerates the translation template and fails when the committed `i18n/messages.pot` differs, and a separate `i18n` job, which needs no Godot, runs the translation gates' self-test, the scan-list check and `i18n_tool.py check` on the game's translation files. The workflow also supports manual runs. The check step has a 10-minute limit on top of each suite's own; failing or cancelled check logs are retained as downloadable artifacts for seven days. Log pipelines retain the command's failure status.

Every pull request runs docs type checks, the docs tests and a production Pages build before merge. Main-branch docs changes then deploy the website to GitHub Pages, one deployment at a time in push order. Build and deployment jobs have time limits. A newer push to a pull request cancels that pull request's older runs; every push to main runs in full.

The **Test builds** workflow exports the macOS and Windows test builds described below. It runs beside the checks rather than after them and is not a required check, so a failed export does not block a merge, and a failed check does not stop the builds. It does not create installers or releases. `scripts/get-export-templates.sh` takes the five files the presets need from Godot's official 4.7.2 template archive and checks each against a pinned checksum: the macOS and Windows debug templates, `version.txt`, and `icudt_godot.dat`, ICU's line-breaking data, which an export packs once a Chinese, Japanese, Korean or Thai translation is registered. `scripts/export-game.sh` fails an export that logs Godot's fallback to the editor's own copy of that data instead.

## Test builds

Every push to main and every pull request from a branch of this repository builds the game for macOS and Windows, so you can try the current state of the work without installing Godot. Pull requests from forks get no builds, since those would be programs built from code nobody has reviewed yet.

These are **debug** builds of the source game, not releases:

- The debug tools above are on from the start, with no code needed.
- They are **not signed** with a developer certificate, so macOS and Windows warn the first time you open one.
- Each is kept for **14 days**, then deleted.
- The repository is public, so **anyone signed in to GitHub** can download them. You need to be signed in; nothing else is required.
- Nobody plays a build as part of making it: a green run means the export worked and the package holds what it should, not that the game was played on that system.

### Download a build

1. Open the [Test builds runs](https://github.com/MrDemonWolf/wolf-override/actions/workflows/builds.yml) on GitHub, signed in, and choose the run for the commit or pull request you want (pull requests also link to it under their checks).
2. The run's summary lists the two downloads with their sizes: `wolf-override-macos-debug-<commit>.zip` and `wolf-override-windows-debug-<commit>.zip`, where `<commit>` is the first seven characters of the commit it was built from. The same files are under **Artifacts** at the bottom of the page.

With the [GitHub CLI](https://cli.github.com/) you can also run `gh run download <run id> --repo MrDemonWolf/wolf-override --name wolf-override-macos-debug-<commit>.zip`. The CLI unzips it for you into a folder of that name, so there is nothing left to unzip, and macOS does not flag the app it saves: it opens without the Gatekeeper steps below.

Each zip has a `licenses` folder beside the game with the game's own licence (GNU GPL version 3 or later), the notices for Godot Engine, the components inside it and the game's two typefaces, and a short `README.txt` naming the commit it was built from and linking its source. The art and other media have separate rights that the GPL does not cover; see [Legal](/docs/legal/).

### Open it on macOS

The macOS build is one app for both Apple silicon and Intel Macs (macOS 11 or later on Intel, 13 or later on Apple silicon). It is signed ad hoc, which lets it run but does not satisfy Gatekeeper.

1. Unzip the download and open `WOLF--OVERRIDE.app` (the two slashes of the name become dashes).
2. macOS says it cannot check the app. Click **Done**, not **Move to Trash**.
3. Open **System Settings → Privacy & Security**, scroll to **Security** and click **Open Anyway** beside the message about the app. The button is there for about an hour after you tried to open it.
4. Confirm with your password. Later launches open normally.

On macOS 15 and later, Control-clicking the app and choosing **Open** no longer gets past this. Instead of steps 2 to 4 you can run `xattr -dr com.apple.quarantine WOLF--OVERRIDE.app` in Terminal, in the folder you unzipped it to. `WOLF--OVERRIDE.command` beside the app starts the same game from Terminal, so its log shows there.

### Open it on Windows

The Windows build is for 64-bit Windows.

1. Right-click the downloaded zip, choose **Extract All**, and open the extracted folder.
2. Run `WOLF-OVERRIDE.exe`.
3. At **Windows protected your PC**, click **More info**, then **Run anyway**.

`WOLF-OVERRIDE.console.exe` runs the same build with its log in a console window, which helps when reporting a crash. If **Smart App Control** is on, Windows blocks unsigned programs outright and offers no way to allow one, so these builds cannot run on that PC.

### Saves and settings

A test build uses the same user data folder as a source run of the game, so it shares its saves, settings and debug unlock: on macOS `~/Library/Application Support/Godot/app_userdata/WOLF--OVERRIDE`, on Windows `%APPDATA%\Godot\app_userdata\WOLF--OVERRIDE`. Move that folder aside first if you want a clean start. Bug captures from **F12** are written to its `debug-captures` folder.

## What has been observed

Godot 4.7.2 headless import, scripted state, M0 scene, chapter scene, and input/settings checks passed locally in the prior source-build review. Scene checks exercise both door routes, both mirror routes, and Continue restoring chapter progress. Engineer movement and WOLF's follow behavior were observed in a partial graphical playtest of the first corridor. Rendered touch, pause, and settings frames were inspected. Complete routes have not been played by hand.

The Service Junction, the closer play camera, the layered room art, the station props, the redrawn characters and the sounds were checked only by the headless suites above and by rendered still frames at 960×540; the sharper character sprites and the 1280×720 first window were also checked in stills at 1280×720 and 1920×937. None of them has been played by hand, so their feel, timing, readability and sound are not yet validated.

The text suite (October 15, 2026) reads every line constant and every line the game says through its dialogue box in `main.gd`, with each provisional engineer name, splits each into its boxes and requires one speaker per box, at most two rows of at most 42 characters at 100% text size, fewer than 20 words, a reading time of at least 0.33 seconds a word, and no word changed by the split. It then plays through the opening, the corridor, Records Access and the Service Junction's knockdown cards and measures every box shown on screen, checks that the first controllable frame shows only the name card and the move prompt, that the Records Access exit no longer holds the engineer and its last line clears once they walk on, that touch answers sit at the bottom without numbers and the hint names the **CRANK** button and stays clear of the touch buttons, that a station's answer or the route hint cutting into WOLF's purge line or the Records Access closing lines (the engineer keeps control while they play) brings the line back after it at the box it was on, and that **USE** at the breaker or the exit brings it back first, and that **TEXT SIZE** saves, reloads and scales the dialogue, hint, cards, tutorial and station names (at 200% every box shown took at most two rows), with the answer buttons inside the screen's 20-pixel side margin and, on touch, the top card clear of the **DEBUG** button where it shows. At every text size it also jumps to the corridor, Records Access and three Service Junction states and requires no two station names to overlap, each to keep its bottom edge where it was at 100%, and the corridor's breaker and relay names and the **COOLANT FAULT** tag not to be faded at the edge of the view at the start, and the **MANUAL BYPASS** name (at the view's edge there, a little faded at 100% and faded out at larger sizes) to show in full with the engineer beside the relay (the camera is snapped to its new place first, since it eases in time and a headless run's frames are short); the Service Junction's valve plate is also put through each of its names and must stay on its line and clear of the **LINE** caption. At every size, with keys and on touch, a fresh game also requires the opening's hint line to stand below the top card and, after the first step, on the step's own frame and again once the opening lines' first box is up, the tutorial prompt to cover no station name, neither character, the box, a top card that shows, **PAUSE**, **DEBUG** or the touch buttons, and to lie over at most a tenth of its area of the machines (at 200% on touch it rests on the edge of the purge display); a prompt hidden behind a box must leave the hint line empty too. On touch it requires a box, with a speaker and without, to stay clear of the arrows and **USE**, the hint bar to stay clear of the box, and the corridor's **COOLANT RELAY** name and **COOLANT FAULT** tag to stay clear of **PAUSE** at every size. Rendered stills at 1280×720, 960×540 and the 2400×1080 and 2556×1179 phone shapes back these up; none of it has been read by a player on a screen.

The language suite (`i18n_test`, October 16, 2026) checks the groundwork for translations. Only English is offered yet, and nothing on screen changes. It requires the suite to start in English (the `--language en` above), the language table `apps/game/i18n/languages.json` to hold the twelve planned language files, each with a picker name, a review state, a fallback font, a reading speed and a row limit, and nothing to be offered whose fonts are not in the build. It resolves 39 locales through the game's own table (Mexico, Argentina and the US to Latin-American Spanish, Spain to Spain's file, Portugal to Brazilian Portuguese, Taiwan, Hong Kong and Macao to Traditional Chinese, and Ukraine never to Russian) and reads the saved language. Each language's picker name and machine-translation tag must be drawable by the game's fonts with only that language's own fallback behind them, and a Chinese character planted in a German catalog must fail that check. With made-up Simplified and Traditional Chinese catalogs, and Latin-American and Spain Spanish ones, a line only one file of a pair has must show English in the other, and the same lookup with every catalog left registered must show the other file's text, so the check can fail. It also requires the offered languages other than English, the translation files in `apps/game/i18n/` and the catalogs `project.godot` registers to be the same set, so no language is offered without its file and no file ships unoffered (a planted German file fails it). The overflow check the later language work uses is tried on planted labels and buttons, one for each case the research prototype missed (text inside a container, text cut short with an ellipsis or clipped, and text that grows too tall or off the bottom of the screen), each beside a twin that fits, and on the English title, where it must find nothing. All 25 suites also passed with the computer's language set to Spanish. These are headless checks: no translation exists yet, and none of this has been seen on screen.

The same suite checks the bundled fonts (October 16, 2026). No game font may ask the operating system for a missing character, so a character missing from the game's fonts shows the same on every computer and these checks tell the whole story. The Japanese, Korean, Simplified and Traditional Chinese subsets must each draw every character of their fixed list (3,491, 3,203, 4,337 and 5,790 characters, among them the language's own name and "machine translation" tag), and a character outside every list must be missing. Together the four subsets must stay within 5,000,000 bytes, and within 10,000,000 bytes with Godot's line-breaking data, the budget of localization decision D7 (today 3,997,912 and 8,795,384). Every character in the game's scripts and scenes must be drawable by each theme font in English (it found ten outside plain ASCII, among them the touch arrows), and Roboto's line height must stay the same with the small symbols font chained behind it, from 12 to 40 px. Turning the operating-system fallback back on for one font, planting a character the Korean subset lacks in its list, or unchaining the symbols font each failed the suite. These are headless checks: no Chinese, Japanese or Korean text has been seen on screen in the game build.

A station's answer that cuts into a line said in several boxes never drops a box (October 15, 2026). The scene suite reads the purge display with no frame passing in between, first ahead of the opening lines (the first box comes back after the display's text, then the rest) and then over the opening exchange (it comes back after the display's text and before WOLF's stakes line). Before, which box was up when the display was read depended on how fast the machine ran, so on a busy machine the exchange could be replaced for good and the check failed now and then; it passed 20 runs in a row with eight other Godot runs going at once. The settings suite checks the Display tab under its **THE DEN / LOCAL CONFIGURATION** heading: no graphics card or renderer line, and the window-size sentence only when the game runs as a phone or tablet build.

Two suites guard the sounds without anyone listening. The sound bank's suite scans every game script for the clip names it passes to the bank (to play, stop or crossfade) and fails on a name the bank does not have, which is how the corridor's **MANUAL BYPASS** had played no hiss; a debug build also warns when a clip name is unknown. The press-sound suite plays both relay routes through the corridor and Records Access, the Service Junction's lane answers and its exit with the game's own input, and requires every press that changes the game's state to start a sound in the bank and change what the screen says within one frame; it also checks that the bypass hisses while it is cranked and that the relay's **COOLANT FAULT** tag is gone at the safe point on both routes. They watch which clips the bank starts, not the speakers: whether the sounds are audible, balanced and pleasant has not been checked by ear.

The Service Junction's fuse, the tank drop and the cranks have their own timing checks (October 13, 2026). The junction suite steps the lit fuse at 60 frames a second and requires it to last 2.5 seconds with five ticks half a second apart, the last half a second before the blast, the blast stripes to pulse once per tick at no more than 2 Hz, and every tick to be played. The sentry suite steps the patrolling sentry frame by frame and requires it to stay over the floor brackets at least half a second on every patrol pass, and a drop pressed at any moment of a patrol pass to hit through a window of at least half a second. Because the patrol turns just past the mark, inside the window, each patrol pass measures about 0.9 s, in past the mark and back out (about 1.0 s until the patrol's turn moved 9 pixels further from the alcove with the sentry's drawn contact range); a straight crossing at patrol speed would be about 0.53 s, and one at chase speed about 0.32 s. The crank suite presses interact at the **MANUAL BYPASS** and the junction valve and requires the wheel to have turned and the ratchet to have clicked on the first frame Main sees the press at each of them, the bypass held from no notches to finish after 2.0 seconds of held time (adding up the frames the game ran with the press down, so the old 3.2 seconds fails it), and, with **TOGGLE HOLDS** on, a single press to finish either crank while a move, a pause or a second press stops it; it also checks that the setting is saved and read back. The photosensitivity estimate was rerun on rendered frames (the render container, 300 frames at 60 frames a second from the lit fuse through the knockdown, with Reduced Motion off and on): the area flashing more than three times a second stayed under WCAG's general-flash threshold, at most about 12% of the worst-placed 10-degree patch (limit 25%) at the blast and about 2.5% while the fuse burns, with no red flash. That is an estimate from rendered frames, not a measurement on a display or phone, and none of these timings has been played by hand.

The wording approved on October 13, 2026, with the four lines approved on October 14 that say WOLF holds back, has its own suite. It checks every changed line against the approved text, that the changed lines it lists fit in boxes of at most two rows of 42 characters with the longest preset name (one long WOLF line in the junction is left for a later pass), that no cut line is left in the game's player text or shown in the opening, that the trust line after first control shows as two boxes in order for their reading times (pressing interact at the purge display or the breaker during the first box only delays the rest, which still come in order; a line that moves the story on, such as the tank landing or the clamp letting go, drops the boxes still to come instead), the Service Junction's goal-only entry and WOLF's warning after it, and the junction's hint ladder (stepped by hand: WOLF's look and the breaker's pulsing lamp at 45 seconds, the engineer's line at 90 and the whole chain in two boxes at 180, nothing during a choice, and nothing once the breaker is armed). For every refused press in the junction it presses interact with the game's own input and requires the clunk to start, that station's lamp to flicker and the line to show within 6 frames, and the box to blink when the same press comes again; walking into the sealed door must thud, flicker its lamp and stop the engineer at its face, with the line on the first bump only, and interact pressed 30 or 90 frames after letting go there (once the engineer has stepped off the valve's body) must still get the door's line, while a step away gets the valve's again. After a sentry knockdown, its two-row card keeps its box and where play resumed follows in the next. In real frames it also walks to the rubble line straight after the door goes, and after waiting at the door, and requires the second box (the sentry waking) to show before WOLF's question and to be up its reading time first, with the engineer held at the rubble line meanwhile; it requires WOLF's "The tank takes a moment to fall." not to come back after the clamp lets go or the tank lands; and after a real missed drop it requires the order to get back over the rubble to come as the sentry swings, within 0.8 seconds of the miss, for an engineer who stays at the release, to be left out for one already back over the rubble, never to show again after the sentry gives up, and the winch's line to come after the miss's boxes. The sentry suite also retreats over the rubble at once after a miss with WOLF drawing the sentry and requires WOLF breaking off to show after the sentry gives up, with no order to get back over the rubble. These are headless checks and still frames; how the refusals, the bump and the hint timing feel has not been played by hand.

Knockdowns and the sentry have their own checks (October 14, 2026). The impact suite also checks the knockdown's timing decided on October 14 (Q17), on the first knockdown and a repeat, in the game's own time and to the frame: a press before 0.9 seconds does nothing and no prompt shows, the card takes **RETRY** from the frame that reaches 0.9 seconds and the hint then reads **E  RETRY** (**TAP RETRY** on touch, with **USE** reading **RETRY** and no arrows), the card is still up 2.5 seconds after the hit when nobody presses, and control comes back 0.6 seconds after the press (0.25 seconds of fade out and 0.35 of fade in), so about 1.5 seconds after the hit for a press at once; it counts the press's own frame, where the fade takes its first step, so a long frame there on a busy machine no longer makes it fail (with a 150-millisecond stall forced at the press, the old count failed and the new one passes). The other suites that knock the engineer down press **RETRY** the same way. The impact suite requires the knocked-down engineer to play the painted collapse frame by frame, slumping forward the way they faced without ever turning round (facing right, and walking in facing left), end up lying with their soles on the floor line (never tilted), with their floor reflection mirroring the lying body and their shadow under all of it, to stand up again as drawn before, and with Reduced Motion to lie down at once; it also reads the collapse image and requires each frame's soles on its bottom row, so nothing is drawn below the floor. The sentry suite watches every frame of its scene routes as drawn, from about 40,000 to about 190,000 Service Junction frames a run depending on how busy the machine is (WOLF drawing the sentry, timing the drop alone, misses, chases, the coolant cloud and every sentry knockdown): on none of them may the sentry's drawn body overlap the engineer's, standing or lying, its beam run past the face of the **EXIT BOLT** box or of the tank at the beam's height ahead of its scanner, or reach further than its 180-pixel sight, and the exit bolt's feed may never cross the tank. The room-lights suite checks at every position the sentry can stand that the drawn beam ends where its sight does, and the junction suite that the relief vent's grate is drawn over its steam. The sentry suite's chase knockdowns face each way (towards the sentry, away from it, and out in its lane facing back towards the alcove, where the engineer slumps forward where they stood rather than being dragged back), and in every one the engineer goes down the way they faced and the sentry ends clear of the body; with Reduced Motion, where the body lies down at once, the sentry must already stand clear of it on that first drawn frame; walking into the coolant cloud facing the tank, the lying body must end clear of the tank, and the frame watch also requires the lying engineer's painted body never to overlap a low tank. The junction suite knocks the engineer down with the door's blast while they face it, at the valve and right up against the door, and requires their whole lying body to end clear of the blast door's near column and the stub of wall in front of it, whose pixels it reads from the image; with the door down it also knocks them down just past the doorway facing back, with Reduced Motion off and on. The sentry suite also walks the engineer into the back of a patrolling sentry and into the front of one locking on, and requires them to stop where the two bodies touch on every drawn frame; the frame watch looks at each frame once the game has finished it, so it sees what is drawn. The sentry suite lets the engine take at most one physics step per drawn frame, so on a busy machine the run slows down instead of taking several steps between two drawn frames, and what it checks does not depend on how busy the machine is; it passed 20 runs in a row. The patrolling sentry rolls on after the engineer is held at its back, so on a drawn frame they may be one of its steps behind it, and the check allows exactly that step. The one locking on is met as it comes down from the far end of its lane, right of the hanging tank, so the knockdown that follows lands clear of the tank however the frames fall; before, it was met wherever it happened to be, and on some runs the engineer went down under the tank's base. At the far end of its patrol the sentry passes behind the **EXIT BOLT** box, which is drawn again over the machine and its beam wherever they cross it; on every frame where the sentry's body or beam crosses the box (about 15,000 to about 80,000 frames a run), the frame watch requires all of that crossing to be under the redrawn box. The bolt's feed beside the box (its cable box, conduit and floor gland) is drawn again with it, and on every frame where the sentry crosses a part of the feed the watch requires that crossing to be covered too; the junction suite checks that the whole feed lies inside what is drawn again and that the redrawn box's lamp dims with the lamp when a refused press flickers it. The debug tools suite also checks that the beam's declared box matches what it drew when its sight ends inside the alcove. The knockdowns and the beam were also compared in rendered stills from scripted play at 1280×720 and in a 2400×1080 phone shape, before and after, with the beam also viewed under protanopia and deuteranopia simulations. A temporary iOS simulator export built and launched on two booted iPhone simulators; the iPhone 17e title screen was inspected. The macOS and Windows test build exports were run headless and their packages checked: the app's executable bit and ad-hoc signature, the embedded Windows pack, the in-game changelog and font licences inside, and no tests or notes. Graphical route play, hardware input, opening an export on its system, signing, and physical devices remain separate gates. A green workflow does not certify a finished game or release package.

## Contributing and reporting problems

Use a focused branch and include relevant checks in a pull request. Keep the Godot pin, stable narrative IDs, existing asset sources, and engineer-only viewpoint intact. Follow the [public agent guide](https://github.com/MrDemonWolf/wolf-override/blob/main/AGENT.md).

Report reproducible bugs through [GitHub Issues](https://github.com/MrDemonWolf/wolf-override/issues) with OS, Godot version, input method, and steps. Private story drafts belong in private notes, not public issues, pull requests, or exported site content.
