## Run the checks

From the repository root:

```sh
bun run game:check
bun run docs:check
bun run docs:test
bun run docs:build
```

`bun run game:check` runs the Godot import twice and then every `apps/game/tests/*_test.gd` suite, up to four at a time, each with its own temporary user data folder, so it never touches your own saves or editor settings. The first import may report only the known font errors of a fresh checkout and the second must be error-free. A suite fails if it reports an error, leaks objects at exit (it is then run once more with verbose output, so its log names them) or is still running after 240 seconds, when it is stopped and reported as hung; each import pass has the same limit. This works on macOS without GNU `timeout`. Set `GODOT_BIN` if `godot` is not on your path, `CHECK_JOBS=1` to run the suites one at a time, or `SUITE_TIMEOUT` to change the limit. Logs are kept, and their folder printed, only when a check fails.

The same script keeps the in-game changelog in step with this website: it regenerates `apps/game/assets/changelog.txt` from `apps/docs/content/docs/changelog.mdx` with `python3 scripts/export_changelog.py` (Python 3, standard library only) and fails when the committed text differs. After editing the changelog, run that script and commit the result with the docs change. The file is a plain `.txt`, which Godot does not pack by default: the export presets in `apps/game/export_presets.cfg` include it (and the two font licences) by name, and any new preset must too, or the in-game screen shows its "missing from this build" line.

The Godot commands check import, state logic, both scripted door routes, both Records Access mirror routes, the Service Junction's pressure-line timing, held crank, blast, the sentry's patrol, sight, lock-on pause, chase and hold on WOLF, the tank's hit window, miss cloud and rewind, both answers at the rubble line with either relay memory, the exit bolt and closing scene, every knockdown's retry, all four autosaves and Continue from each, save/load, the lamp flicker's timing limits, lockdown beacons that settle from the save state, hidden rooms that stop their dust and light, a sentry beam drawn to its real sight range, with a gap over the alcove where it cannot see, the pressure bulkheads' shared cut and draw order, station name plates (the relief vent's among them) that share one row without overlapping in any state, station names in every room that fade at the edge of the view, an engineer who sidesteps out of any machine they stop over, machine lights and plates drawn behind both characters, near pipe columns and bulkhead pillars that fade back from a character behind them, and the debug tools' gating, unlock codes, overlay, state dump, bug capture and zone drawing (each hitbox matches its real shape, each render box its sprite or control, each use range the rule that answers interact, and none of it runs while hidden), and the debug menu with keyboard, controller and touch: every jump, the choice presets, every cheat including slow motion and frame stepping, each forced knockdown, the door fuse and the tank drop, the save actions and the effect switches. Bun checks docs types and builds the static Pages site. Headless checks do not establish how a route feels on screen; exports and devices need separate checks.

The game starts on the MrDemonWolf, Inc. logo screen, which hands over to the title once it has played. Scripts and capture tools that launch the game normally can pass `-- --skip-logo` (for example `godot --path apps/game -- --skip-logo`) to go straight to the title; a headless run always skips it, and suites that load `scenes/main.tscn` directly are unaffected.

## Debug tools and cheat codes

The game has debug tools for anyone testing it, so you can see what it is doing and keep a record of a problem. In a debug build (the editor, a source run with the standard Godot binary, or one of the [test builds](#test-builds)) they are always available. In any other build they stay hidden until you enter a code on the title screen:

| Input | Code |
| --- | --- |
| Keyboard | Type `WOLFDEN`, in capitals or not: Shift, Caps Lock and the other modifier keys do not break it, any other key does. |
| Controller | On the D-pad: Up, Up, Down, Down, Left, Right, Left, Right, then B (the east face button), then A (the south face button). The final A does not press the focused menu button. |
| Touch | Tap the WOLF//OVERRIDE logo mark at the top right seven times, each tap within a second of the last. |

A short **Debug tools unlocked** note confirms it. The unlock is saved with your settings, so the tools stay available on later launches until they are locked again; locking also forgets the saved unlock.

Once the tools are available:

| Input | What it does |
| --- | --- |
| **F3** | Cycles the overlay: off, performance, state, state and zones. |
| **F5**, **F6**, **F7** | On the zones page: turn the zones, the hitboxes and the render boxes on or off. The legend's buttons at the top of the screen do the same with a tap or click. |
| **LB**, **RB**, **View** (Select / Back) | The same on a controller, on the zones page: zones, hitboxes, render boxes. A button you have bound to a game action in Settings is left alone. The legend's caption names the keys, buttons or taps for the device in use. |
| **F12** | Saves a bug capture. |
| `` ` `` (backquote), both sticks pressed together (L3 + R3), or the **DEBUG** button | Opens the debug menu, or closes it when it is open. |
| **.** (period), **RB**, or the **STEP** button | While frame stepping: lets one frame of play through. |
| **Esc**, **B**, or the **RUN** button | While frame stepping: plays on at normal speed. |

- **Performance page:** frames per second, frame and process time, memory, and node, object and draw-call counts. Godot reports the game's own (static) memory only in debug builds, so in an unlocked release build that figure reads **n/a** and the page shows video memory instead.
- **State page:** the room, the current beat and objective; the engineer's position, facing and what they are doing; WOLF's position, where he is heading and why (following, scouting, holding a spot, drawing the sentry or refusing); in the Service Junction the sentry's state, position, facing, sight range and who it is fixed on, the pressure line's state, gauge, turns and fuse, the tank arm, the exit bolt and which hazards are armed; the run's relay, mirror and lane choices and WOLF's memory; the save format version, whether a checkpoint is on disk and where it stands; and whether cheats were used. The overlay keeps updating while the game is paused, and it reads the save file at most once a second.
- **Zones page (state and zones):** the state card, plus a drawing over the game that follows the camera, worked out every frame from the same shapes and constants the game's rules use, in three colour-coded layers named in a small legend at the top:
  - **Zones** (cyan), as bars in lanes under the floor line with end ticks: each station's interact range (drawn faint while it does not answer, such as the **TANK RELEASE** before the door is down), the spots the engineer steps to, WOLF's spots (with his current target and why, in white), his follow distance around the engineer and the machines he rests clear of, the sentry's lane in the Service Junction (the alcove, the patrol, its sight as an arrow from where it faces, where it watches from), and dashed lines for limits: walls, a shut door's face, how far WOLF follows, the lane entry, the sentry's chase limit and where WOLF asks about the lane. The camera's centre limits and its current position sit on the bottom edge of the screen. A range wholly off screen is listed in captures but not drawn.
  - **Hitboxes** (orange): every collision shape from its real shape (both characters, the floor, the corridor seal and the junction door while they block, the sentry's body, the relief vent and coolant cloud hurtboxes), and the rule ranges that hurt or hit: the vent and cloud by the engineer's position, the door blast (with the room above it shaded), the sentry's contact, the tank's hit range and its footprint. Anything in force right now (an armed hurtbox, a lit fuse, a falling tank) turns red.
  - **Render boxes** (yellow-green): the on-screen rectangle of every sprite, prop, plate layer, label, button and panel, and of props the game draws in code (the sentry's sight beam and lens, the hatch doorway, the bypass pipe and post, room lights and beacons), with its node name, z-index and canvas layer (for example `BodySprite z2`, `PauseButton z0 L2`), so overlaps and anything drawn inside something else stand out. Boxes hidden behind the title or the end card, faded out or off screen are listed in captures but not drawn. Boxes for props drawn in code come from what the renderer recorded, which Godot reports only in editor builds; in an exported build only props that declare their area (the sentry's beam) get one, and captures say which source each box used.

  Nothing in the drawing covers the touch arrows, **USE**, the answer buttons, **PAUSE**, or the text of the hint, the dialogue, the tutorial prompt or the top card: lines, bars and fills are cut around them, and every name is placed where it overlaps none of them, no character and no other name (smaller boxes are named first; a name moved away from its box is joined to it by a short line). A name with no room left is not drawn; captures still list it, with `label_hidden`. Captures also list the protected areas under `keep_clear`. The drawing steps aside with the overlay for Pause, Settings and the game's cards, and costs nothing while another page is up.
- **The game's own screens come first:** the overlay steps aside while Pause, Settings, the END OF SLICE card or the title's Credits or Changelog is open, and in the touch layout while a question's answer buttons are up, and comes back when they close. It stays up during a question in the keyboard and controller layout, where the answers are clear of it. While the corridor's tutorial prompt is up, the state and zones pages narrow to end left of it, so its control instructions stay readable, and widen again once it has gone.
- **Bug capture:** writes a screenshot and a JSON file with the same data, plus positions and flags, to `user://debug-captures/` (Godot's user data folder for the game), named by date and time, and shows the path. A headless run writes the JSON only. The JSON's `geometry` lists every zone, hitbox and render box as numbers, whether or not they were drawn: node path, `world_rect` and `screen_rect` as `[x, y, width, height]` (screen rects in the 960×540 canvas, with the scale to window pixels beside them), z-index, canvas layer, visibility, alpha and draw order, plus the camera. Capture scripts can call `debug_tools.dump()` on the game's main node to log the same data beside their own screenshots, or `await debug_tools.capture_with_boxes()` to save a capture with every box drawn into the screenshot, whatever page is up; the tools' own note (an earlier capture's path, a jump's result) is hidden first so it is never in the picture. If the window draws no frame within ten frames (hidden or covered), that call still saves the JSON, skips the out-of-date screenshot, reports `with_boxes: false` and puts the page back.
- **DEBUG button:** in touch play a small **DEBUG** button sits at the top right, a finger's gap left of **PAUSE**, clear of the characters, **USE** and the arrows. It hides while Pause, Settings, the END OF SLICE card, Credits or Changelog is open, or a controller is in use.

### Debug menu

The debug menu holds the game still while it is open, as Pause does, and sits to the right of the overlay so the state page stays readable beside it. It uses the game's own menu card and buttons. With a keyboard or controller, focus starts on the page's tab: move along the tabs to change page (or press **LB** / **RB**), move down into the page and confirm to use a button. On touch, tap a tab or a button. **Esc**, **B**, Android Back, **CLOSE** or a tap outside the card closes it; it does not open while the game's own Pause or Settings is up. Every action notes what it did, or why it cannot, under the page. Actions that close the menu so their result plays (jumps, forced knockdowns, the fuse, the tank and reloading) leave that note for a few seconds at the top of the screen, between the top card and **PAUSE**, over nothing but the ceiling. On the zones page, whose legend has that spot, the note sits just below the answer row or under **PAUSE**, whichever covers neither character nor the Service Junction's tank. Opening the menu again clears it.

| Page | What it does |
| --- | --- |
| **JUMP** | Puts you straight at a point of the slice: the opening, the start of the corridor, WOLF's relay question, the corridor's safe point, the start of Records Access, Records Access with both copies made, the start of the Service Junction, the lane after the door blast (with WOLF already asked and answered from the **CHOICES** page), the sentry down, or the **END OF SLICE** card. Each jump builds the run through the game's own save steps from the **CHOICES** presets and loads it as Continue does. A jump to a point the game autosaves at writes that checkpoint, as play does when it gets there, replacing the save on disk; the opening, corridor start and relay question leave the save alone. |
| **CHOICES** | The earlier choices the next jump uses: how the relay went (WOLF rushed and the engineer cranked the bypass; WOLF told and taking the contact; or WOLF told and the engineer cranking anyway), who read the mirror (WOLF's readout or the manual port), and how the sentry came down (WOLF draws it, the engineer times it alone, or WOLF refuses). WOLF's lane answer follows the same rule as in play, so asking him to draw the sentry after a rushed relay turns into a refusal, and the presets change together and say so. Choosing presets is not a cheat. |
| **CHEATS** | **INVINCIBLE**: no knockdown lands; the door still blows as if the engineer were clear. **FREEZE SENTRY**: the sentry stops moving and changing state (touching one that was chasing still knocks you down unless invincible). **INSTANT CRANK**: holding interact at the junction valve or the corridor's **MANUAL BYPASS** finishes it at once through the game's own crank. **FRAME STEP**: the game holds still and a small bar near the top right lets one frame through per **STEP** (or **.** / **RB**) and plays on with **RUN** (or **Esc** / **B**); a jump or **RELOAD CHECKPOINT** while stepping keeps the game held. **SPEED**: 1x, 0.5x or 0.25x (the game's short impact pauses still dip it further for their moment). |
| **FORCE** | In the Service Junction: knocks the engineer down with the relief vent's, the door blast's, the sentry's or the coolant cloud's own card, with the same short pause, red flash and camera shake as in play, even while invincible, and the beat's checkpoint comes back as usual. **LIGHT THE DOOR FUSE** arms and cranks the pressure line so the door goes a second after play resumes, and where everyone stands then decides the outcome. **DROP THE TANK** lets the tank go from wherever you are; it lands on the sentry only if the sentry is over the floor brackets. Buttons that cannot work now are greyed out, with the reason below. |
| **SAVE** | Shows the checkpoint on disk. **SAVE NOW** writes the current beat through the game's own autosave (only once the first safe point is reached), **RELOAD CHECKPOINT** goes back to it, and **CLEAR SAVE** deletes it after a second press. |
| **VIEW** | **OVERLAY** steps the overlay's page (for phones, which have no F3), **BUG CAPTURE** closes the menu and saves a capture, and **VISUAL EFFECTS**, **CAMERA SHAKE** and **SCREEN FLASH** turn those off for this session (they are not cheats and are not saved). **LOCK DEBUG TOOLS** hides the tools and forgets the unlock. |

Jumps, cheats, forced knockdowns and the two triggers mark the overlay and every dump **CHEATS USED**, and the state page lists the cheats in force (for example `invincible · 0.5x`). Dumps and captures also list every cheat, preset and switch under `debug.cheats`. Locking the tools, or a build in which they become unavailable, turns every cheat off, puts the speed and the effects back and lets the game run.

While the tools are hidden, or available with the overlay off, the menu closed and no slow motion or instant crank on, they do no work each frame and draw nothing.

The tools live in `apps/game/scripts/debug/` and reach the game only through the main script's typed fields and its public `debug_*` methods (`debug_snapshot`, `debug_new_game`, `debug_load_checkpoint`, `debug_knock_down` and the like, kept together at the end of `main.gd`), never its private ones, so renaming or moving one of those fails when the scripts are parsed instead of when a menu button is pressed.

## Continuous integration

Every pull request and push to main runs a checksum-verified Godot 4.7.2 import and the scripted headless game checks through `scripts/check-game.sh`. The workflow also supports manual runs. The check step has a 10-minute limit on top of each suite's own; failing or cancelled check logs are retained as downloadable artifacts for seven days. Log pipelines retain the command's failure status.

Every pull request runs docs type checks, the docs tests and a production Pages build before merge. Main-branch docs changes then deploy the website to GitHub Pages, one deployment at a time in push order. Build and deployment jobs have time limits. A newer push to a pull request cancels that pull request's older runs; every push to main runs in full.

The **Test builds** workflow exports the macOS and Windows test builds described below. It runs beside the checks rather than after them and is not a required check, so a failed export does not block a merge, and a failed check does not stop the builds. It does not create installers or releases.

## Test builds

Every push to main and every pull request from a branch of this repository builds the game for macOS and Windows, so you can try the current state of the work without installing Godot. Pull requests from forks get no builds, since those would be programs built from code nobody has reviewed yet.

These are **debug** builds of the source game, not releases:

- The debug tools above are on from the start, with no code needed.
- They are **not signed** with a developer certificate, so macOS and Windows warn the first time you open one.
- Each is kept for **14 days**, then deleted.
- The repository is public, so **anyone signed in to GitHub** can download them. You need to be signed in; nothing else is required.
- Nobody plays a build as part of making it: a green run means the export worked and the package holds what it should, not that the game was played on that system.

### Download a build

1. Open the [Test builds runs](https://github.com/MrDemonWolf/wolf-override/actions/workflows/builds.yml) on GitHub, signed in, and choose the run for the commit or pull request you want (pull requests also link to it under their checks).
2. The run's summary lists the two downloads with their sizes: `wolf-override-macos-debug-<commit>.zip` and `wolf-override-windows-debug-<commit>.zip`, where `<commit>` is the first seven characters of the commit it was built from. The same files are under **Artifacts** at the bottom of the page.

With the [GitHub CLI](https://cli.github.com/) you can also run `gh run download <run id> --repo MrDemonWolf/wolf-override --name wolf-override-macos-debug-<commit>.zip`. The CLI unzips it for you into a folder of that name, so there is nothing left to unzip, and macOS does not flag the app it saves: it opens without the Gatekeeper steps below.

Each zip has a `licenses` folder beside the game with the game's own licence (GNU GPL version 3 or later), the notices for Godot Engine, the components inside it and the game's two typefaces, and a short `README.txt` naming the commit it was built from and linking its source. The art and other media have separate rights that the GPL does not cover; see [Legal](/docs/legal/).

### Open it on macOS

The macOS build is one app for both Apple silicon and Intel Macs (macOS 11 or later on Intel, 13 or later on Apple silicon). It is signed ad hoc, which lets it run but does not satisfy Gatekeeper.

1. Unzip the download and open `WOLF--OVERRIDE.app` (the two slashes of the name become dashes).
2. macOS says it cannot check the app. Click **Done**, not **Move to Trash**.
3. Open **System Settings → Privacy & Security**, scroll to **Security** and click **Open Anyway** beside the message about the app. The button is there for about an hour after you tried to open it.
4. Confirm with your password. Later launches open normally.

On macOS 15 and later, Control-clicking the app and choosing **Open** no longer gets past this. Instead of steps 2 to 4 you can run `xattr -dr com.apple.quarantine WOLF--OVERRIDE.app` in Terminal, in the folder you unzipped it to. `WOLF--OVERRIDE.command` beside the app starts the same game from Terminal, so its log shows there.

### Open it on Windows

The Windows build is for 64-bit Windows.

1. Right-click the downloaded zip, choose **Extract All**, and open the extracted folder.
2. Run `WOLF-OVERRIDE.exe`.
3. At **Windows protected your PC**, click **More info**, then **Run anyway**.

`WOLF-OVERRIDE.console.exe` runs the same build with its log in a console window, which helps when reporting a crash. If **Smart App Control** is on, Windows blocks unsigned programs outright and offers no way to allow one, so these builds cannot run on that PC.

### Saves and settings

A test build uses the same user data folder as a source run of the game, so it shares its saves, settings and debug unlock: on macOS `~/Library/Application Support/Godot/app_userdata/WOLF--OVERRIDE`, on Windows `%APPDATA%\Godot\app_userdata\WOLF--OVERRIDE`. Move that folder aside first if you want a clean start. Bug captures from **F12** are written to its `debug-captures` folder.

## What has been observed

Godot 4.7.2 headless import, scripted state, M0 scene, chapter scene, and input/settings checks passed locally in the prior source-build review. Scene checks exercise both door routes, both mirror routes, and Continue restoring chapter progress. Engineer movement and WOLF's follow behavior were observed in a partial graphical playtest of the first corridor. Rendered touch, pause, and settings frames were inspected. Complete routes have not been played by hand.

The Service Junction, the closer play camera, the layered room art, the station props, the redrawn characters and the sounds were checked only by the headless suites above and by rendered still frames at 960×540; the sharper character sprites and the 1280×720 first window were also checked in stills at 1280×720 and 1920×937. None of them has been played by hand, so their feel, timing, readability and sound are not yet validated.

The MrDemonWolf, Inc. logo screen was checked by its headless suite and by rendered stills at 1280×720, 1920×1080 and a 2340×1080 phone shape, including a pixel comparison of its first frame with the boot splash image. The suite and headless probes also cover presses just after the logo (held off the title for 0.6 seconds), the sweeping loading bar, and closing the game while the title loads. A saved window size was seen applying on the logo's first frame in the render container; saved fullscreen there applies only when no size change comes with it, as it did before the logo existed, since the container has no window manager. The engine's boot splash itself cannot be captured, and the logo has not been watched in a game window or on a device.

A temporary iOS simulator export built and launched on two booted iPhone simulators; the iPhone 17e title screen was inspected. Touch gestures, controller hardware, and physical devices were not tested. Godot's official 4.7.2 iOS template contained only x86_64 simulator code in a slice labeled arm64; the local simulator build used a temporary version-matched arm64 library. No distributable iOS package is published.

The macOS and Windows test build exports were run headless and their packages checked: the app's executable bit and ad-hoc signature, the embedded Windows pack, the in-game changelog and font licences inside, and no tests or notes. Neither build has been opened on a Mac or a Windows PC as part of this.

Graphical route play, hardware input, opening an export on its system, signing, and physical devices remain separate gates. A green workflow does not certify a finished game or release package.

## Contributing and reporting problems

Use a focused branch and include relevant checks in a pull request. Keep the Godot pin, stable narrative IDs, existing asset sources, and engineer-only viewpoint intact. Follow the [public agent guide](https://github.com/MrDemonWolf/wolf-override/blob/main/AGENT.md).

Report reproducible bugs through [GitHub Issues](https://github.com/MrDemonWolf/wolf-override/issues) with OS, Godot version, input method, and steps. Private story drafts belong in private notes, not public issues, pull requests, or exported site content.
