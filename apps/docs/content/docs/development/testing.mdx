## Run the checks

From the repository root:

```sh
bun run game:check
bun run docs:check
bun run docs:test
bun run docs:build
```

`bun run game:check` runs the Godot import twice (the second must be error-free) and every `apps/game/tests/*_test.gd` suite with a temporary user data folder, so it never touches your own saves or editor settings. Set `GODOT_BIN` if `godot` is not on your path.

The same script keeps the in-game changelog in step with this website: it regenerates `apps/game/assets/changelog.txt` from `apps/docs/content/docs/changelog.mdx` with `python3 scripts/export_changelog.py` (Python 3, standard library only) and fails when the committed text differs. After editing the changelog, run that script and commit the result with the docs change. The file is a plain `.txt`, which Godot does not pack by default: any export preset must add `*.txt` to its include filter, or the in-game screen shows its "missing from this build" line.

The Godot commands check import, state logic, both scripted door routes, both Records Access mirror routes, the Service Junction's pressure-line timing, held crank, blast, the sentry's patrol, sight, lock-on pause, chase and hold on WOLF, the tank's hit window, miss cloud and rewind, both answers at the rubble line with either relay memory, the exit bolt and closing scene, every knockdown's retry, all four autosaves and Continue from each, save/load, the lamp flicker's timing limits, lockdown beacons that settle from the save state, hidden rooms that stop their dust and light, a sentry beam drawn to its real sight range, with a gap over the alcove where it cannot see, the pressure bulkheads' shared cut and draw order, station name plates (the relief vent's among them) that share one row without overlapping in any state, station names in every room that fade at the edge of the view, an engineer who sidesteps out of any machine they stop over, machine lights and plates drawn behind both characters, near pipe columns and bulkhead pillars that fade back from a character behind them, and the debug tools' gating, unlock codes, overlay, state dump and bug capture. Bun checks docs types and builds the static Pages site. Headless checks do not establish how a route feels on screen; exports and devices need separate checks.

## Debug tools and cheat codes

The game has debug tools for anyone testing it, so you can see what it is doing and keep a record of a problem. In a debug build (the editor, or a source run with the standard Godot binary) they are always available. In any other build they stay hidden until you enter a code on the title screen:

| Input | Code |
| --- | --- |
| Keyboard | Type `WOLFDEN`. |
| Controller | On the D-pad: Up, Up, Down, Down, Left, Right, Left, Right, then B (the east face button), then A (the south face button). The final A does not press the focused menu button. |
| Touch | Tap the WOLF//OVERRIDE logo mark at the top right seven times, each tap within a second of the last. |

A short **Debug tools unlocked** note confirms it. The unlock is saved with your settings, so the tools stay available on later launches until they are locked again; locking also forgets the saved unlock.

Once the tools are available:

| Input | What it does |
| --- | --- |
| **F3** | Cycles the overlay: off, performance, state, state and zones. |
| **F12** | Saves a bug capture. |
| `` ` `` (backquote), both sticks pressed together (L3 + R3), or the **DEBUG** button | Asks for the debug menu. Until the menu is built, this steps the overlay to its next page. |

- **Performance page:** frames per second, frame and process time, memory, and node, object and draw-call counts.
- **State page:** the room, the current beat and objective; the engineer's position, facing and what they are doing; WOLF's position, where he is heading and why (following, scouting, holding a spot, drawing the sentry or refusing); in the Service Junction the sentry's state, position, facing, sight range and who it is fixed on, the pressure line's state, gauge, turns and fuse, the tank arm, the exit bolt and which hazards are armed; the run's relay, mirror and lane choices and WOLF's memory; the save format version, whether a checkpoint is on disk and where it stands; and whether cheats were used. The overlay keeps updating while the game is paused. The world zone drawing for the fourth page is still to come.
- **Bug capture:** writes a screenshot and a JSON file with the same data, plus positions and flags, to `user://debug-captures/` (Godot's user data folder for the game), named by date and time, and shows the path. A headless run writes the JSON only. Capture scripts can call `debug_tools.dump()` on the game's main node to log the same data beside their own screenshots.
- **DEBUG button:** in touch play a small **DEBUG** button sits at the top right, left of **PAUSE**, clear of the characters, **USE** and the arrows. It hides while Pause is open or a controller is in use.

While the tools are hidden, or available with the overlay off, they do no work each frame and draw nothing.

## Continuous integration

Every pull request and push to main runs a checksum-verified Godot 4.7.2 import and the scripted headless game checks through `scripts/check-game.sh`. The workflow also supports manual runs. The check step has a 5-minute limit; failing or cancelled check logs are retained as downloadable artifacts for seven days. Log pipelines retain the command's failure status.

Every pull request runs docs type checks, the docs tests and a production Pages build before merge. Main-branch docs changes then deploy the website to GitHub Pages. Build and deployment jobs have time limits. This pipeline does not create game installers.

## What has been observed

Godot 4.7.2 headless import, scripted state, M0 scene, chapter scene, and input/settings checks passed locally in the prior source-build review. Scene checks exercise both door routes, both mirror routes, and Continue restoring chapter progress. Engineer movement and WOLF's follow behavior were observed in a partial graphical playtest of the first corridor. Rendered touch, pause, and settings frames were inspected. Complete routes have not been played by hand.

The Service Junction, the closer play camera, the layered room art, the station props, the redrawn characters and the sounds were checked only by the headless suites above and by rendered still frames at 960×540; the sharper character sprites and the 1280×720 first window were also checked in stills at 1280×720 and 1920×937. None of them has been played by hand, so their feel, timing, readability and sound are not yet validated.

A temporary iOS simulator export built and launched on two booted iPhone simulators; the iPhone 17e title screen was inspected. Touch gestures, controller hardware, and physical devices were not tested. Godot's official 4.7.2 iOS template contained only x86_64 simulator code in a slice labeled arm64; the local simulator build used a temporary version-matched arm64 library. No distributable iOS package is published.

Graphical route play, hardware input, exports, signing, and physical devices remain separate gates. A green workflow does not certify a finished game or release package.

## Contributing and reporting problems

Use a focused branch and include relevant checks in a pull request. Keep the Godot pin, stable narrative IDs, existing asset sources, and engineer-only viewpoint intact. Follow the [public agent guide](https://github.com/MrDemonWolf/wolf-override/blob/main/AGENT.md).

Report reproducible bugs through [GitHub Issues](https://github.com/MrDemonWolf/wolf-override/issues) with OS, Godot version, input method, and steps. Private story drafts belong in private notes, not public issues, pull requests, or exported site content.
