## Words used here

- **Localization:** making the game work in another language, including its text, fonts and layout.
- **Catalog (`.po` file):** one language's translated lines.
- **Template (`messages.pot`):** every English line the player reads, the file each catalog is made from.
- **Locale:** a language code such as `es` or `pt_BR`.

## How it works

- **One module:** `apps/game/scripts/i18n.gd` (`I18n`) is the one place that knows which languages exist and which one the game shows.
- **One table:** `apps/game/i18n/languages.json` lists the planned language files. For each: its name in its own language, whether it is offered, its review state, its fallback font, a reading speed and a row limit.
- **English stays inside:** constants, saves, comparisons and tests keep the English words. Text is translated only where it is drawn.
- **Why:** code compares English text (speaker tags, key tokens and the like) and saves store the English choice, so translating earlier would break them.
- **Settings is wired:** Settings applies the saved language (`[general] language` in `settings.cfg`), or the system's when none is saved, as the game loads. Its **LANGUAGE** row on the **GENERAL** tab shows once a second language is offered.
- **Menus are marked:** the title, Pause and Settings text is in the template. Scene captions translate themselves. Captions set in code carry the `I18n.KEY.tr()` mark so the generator finds them. Text built in code (the Settings note, key and button names, Pause's hint) is translated with `tr()` as it is built, and built again when the language changes.
- **The HUD is marked:** hints, objectives, top cards, the tutorial, the touch **USE** button and the CONTINUE and RETRY prompts are in the template. Their Labels translate in code, not by themselves, and the HUD is drawn again when the language changes.
- **Key prompts are templates:** a hint that names a key is written `"%s: arm the breaker."` and built with `HudText.key` (`apps/game/scripts/hud_text.gd`) and a key token. The game still reads the English `E: arm the breaker.`; where it is drawn, `HudText.localise` translates the template and then puts in the key, button or touch word in use, so a translation can move the key. The save-error line and WOLF's manual-port line have a whole touch form of their own ("Tap USE here again.").
- **The story is marked:** narration, dialogue, refusals, knockdown cards, restore lines, the answers and the end card are in the template. The game keeps every line in English and draws it through `I18n.shown`.
- **Speaker and words apart:** a line such as `WOLF: It's down.` is two things in the code, the tag and the words. Only the words are a message, so a translation never holds a tag. The Director's tag is its own message (context `speaker`); WOLF and the engineer's name stay as written. The speaker's colour goes by the English tag.
- **The story's table:** `apps/game/scripts/story_text.gd` (`StoryText`) marks every story line kept in a constant, once, with its note and marks. Lines written inside a function are marked where they are said.
- **Marks for the checks:** each story line carries `i18n: story` (the release gate), its speaker, and on the 26 lines that could show the engineer's gender an `engineer=` mark. WOLF's three callbacks also carry `slot=choice`, and a line whose break matters carries `keep-breaks`.
- **Lines made of several messages:** a knockdown card and the restore line under it, or "Safe point saved." and WOLF's callback, are built with `I18n.join`, so each part is translated on its own.
- **Saved answers:** the save keeps the English answer. WOLF's callback quotes it through `I18n.format`, which translates that quote where it is drawn. An answer saved before October 13, 2026 has older wording that is no message, so WOLF quotes it in English.
- **Dialogue boxes per language:** `DialogueBoxes` reads each language's reading speed and row limit from the table. Chinese, Japanese and Korean rows run to the column, a two-row box is split into two even rows between whole words (after a comma or full stop where one sits near the middle; Korean at a space, `DialogueBoxes.keep_words`), and a box holds as many characters as 20 English words take to read (26 in Japanese).
- **End card:** each row's topic and words are separate messages. `{name}` is filled in after translation by `I18n.fill_named`, which shows the English row if a translation changes the placeholder.
- **The changelog stays English** (decision D4). In another language it opens with one translated line that says so.
- **CONTINUE has two meanings:** the touch button's CONTINUE (go on through lines) carries the `touch button` context, so a language can word it apart from the title's CONTINUE (resume a save).
- **Key names:** `GameSettings.key_name` shows the label printed on the key in the player's layout (`DisplayServer.keyboard_get_label_from_physical`, Windows, macOS and Linux only), and translates named keys such as Escape. A key keeps its QWERTY name where the layout agrees, or where `I18n.game_fonts_draw` says the game fonts lack the label's letter.
- **Filling templates:** text built in code from a template (`"%s  RESUME"`) goes through `I18n.fill`, which shares `I18n.shown`'s guard: a translation with other `%` conversions shows the English instead of a script error.
- **The language list's font:** the list draws with its own font chain (`I18n.picker_font`): Montserrat plus four tiny Noto Sans cuts that hold only the Japanese, Korean and Chinese names and their "machine translation" tags, so those names draw in every language without a CJK font behind the game's fonts.
- **Fonts:** the game never asks the operating system for a missing character. Chinese, Japanese and Korean use bundled Noto Sans subsets: `I18n.use_fallback` puts only the chosen language's subset behind the game fonts. Fonts are credited on [Credits](/docs/credits/#fonts-in-use).
- **Row heights stay English's:** each CJK subset carries Roboto's vertical metrics, so a CJK language never makes a row taller. Noto's own metrics made rows 4 px taller at body size, and fixed-height rows overflowed.

## Where the files are

| Path | What it holds |
| --- | --- |
| `apps/game/scripts/i18n.gd` | The language module |
| `apps/game/i18n/languages.json` | The language table the game and the tools both read |
| `apps/game/i18n/<code>.po` | Catalogs, one per language file: 11 so far |
| `i18n/messages.pot` | The template, outside the game so it is not exported |
| `i18n/glossary.json` | Fixed terms for each language |
| `i18n/style/` | The translators' style guides: one shared, one per language |
| `scripts/i18n/` | The tools below |

- **How a language is reviewed:** [`i18n/README.md`](https://github.com/MrDemonWolf/wolf-override/blob/main/i18n/README.md#review). A language stays labelled "machine translation" until a native speaker reviews it.

## Commands

You need Python 3 (standard library only) and GNU gettext's `msgfmt` (`brew install gettext` on macOS).

- **Template:** regenerate it with Godot's own generator, headless: `scripts/i18n/extract_pot.sh . i18n/messages.pot <log dir>`
- **Scan list:** fail when `project.godot`'s list of files to scan leaves out a scene or script: `python3 -I -B scripts/i18n/i18n_tool.py potfiles apps/game --check`
- **Gates:** run every gate on the catalogs; exits 1 on any failure: `python3 -I -B scripts/i18n/i18n_tool.py check i18n/messages.pot apps/game/i18n <report.json>`
- **Self-test:** check the gates themselves on planted cases: `python3 -I -B scripts/i18n/i18n_tool.py selftest <report.json>`
- **Glossary:** check the glossary and style guides against each other and the language table: `python3 -I -B scripts/i18n/i18n_tool.py glossary`
- **Fonts:** rebuild the bundled Chinese, Japanese and Korean font subsets: `python3 -I -B scripts/i18n/i18n_tool.py fonts <download folder>`
- **Language list fonts:** rebuild only the four tiny cuts the language list uses, with no download: `python3 -I -B scripts/i18n/i18n_tool.py pickerfonts`
- **Parity capture:** capture the routes in a language, or `pseudo` for padded English: `scripts/parity/run.sh capture --language <code> <out dir>`
- **Another keyboard layout:** set `PARITY_KEYBOARD` to an XKB layout (`fr` is AZERTY) to capture key names as that keyboard shows them: `PARITY_KEYBOARD=fr scripts/parity/run.sh capture <out dir> R1`

<Details>
<Summary>Template: when to run it and what it touches</Summary>

- Run it after changing any text the player reads, and commit `i18n/messages.pot`.
- It puts a small editor plugin into `apps/game/addons/` and an entry into `project.godot` for one editor run, and takes both out again afterwards, so commit only the template.
- CI regenerates it and fails when the committed template differs.
- `potfiles` without `--check` prints the line to paste into `locale/translations_pot_files`.

</Details>

<Details>
<Summary>The gates `check` runs</Summary>

- Placeholders, BBCode, speaker tags, line breaks, the key token and the alphabet.
- The glossary in `i18n/glossary.json`: both its required words and the words it says to avoid.
- The engineer is never given a gender; Slavic name endings.
- Polish and Russian one-letter words (such as *w* and *в*) are bound to the next word with a no-break space, so none ends a row.
- Korean particles: none that changes with the last sound (은/는, 이/가, 을/를) is glued to a name or key slot.
- Plural forms and their header.
- Sibling files, such as the two Chinese and two Spanish files.
- Coverage: a language that is offered (`enabled` in `languages.json`) must translate every line of the template.
- Comments that would make Godot skip a line.
- `--back <file>` adds a back-translation's checks.
- `--release` adds the release gates: no fuzzy line in a language marked reviewed, no untranslated line marked as story.
- With no catalogs yet, it checks nothing and passes.

</Details>

<Details>
<Summary>Self-test, glossary and fonts in detail</Summary>

- **`selftest`** runs the gates on 206 planted cases (160 for the line, plural, comment and sibling gates, 9 for the release gates, 6 for the coverage gate, 16 for the glossary on its real terms and 15 broken copies of the glossary and style guides). It fails if any planted error passes or any clean line fails.
- **`glossary`** checks that every one of the 10 languages' 11 files (Italian and Ukrainian, Tier 1, are not covered yet) has a form for every term and a guide with the same sections, that every word is in its language's alphabet, and that a term still left to reviewers requires nothing. It exits 1 on any problem.
- **`fonts`** downloads the Noto Sans CJK 2.004 release files from GitHub into the folder (unless they are there), checks each font's SHA-256, cuts Noto Sans JP, KR, SC and TC down to each language's fixed common character set with HarfBuzz's `hb-subset` (`brew install harfbuzz`), and gives each cut Roboto's vertical metrics. It writes the symbols font Roboto chains and the character lists in `apps/game/tests/support/cjk_charsets.json`, then runs `pickerfonts`, and prints the sizes. Its output is committed, so it only runs again to change a character set.
- **`pickerfonts`** cuts each CJK language's own name and "machine translation" tag out of its committed subset (`picker_font` in `languages.json`) and gives the cut Montserrat's line height, so the list's rows keep their height.
- **Parity capture:** takes any language of `apps/game/i18n/languages.json`, or `pseudo` for English with Godot's pseudolocalization (brackets and 30% padding). Every still's entry in `shots.json` lists the visible text that overflows its control, the characters its font cannot draw and, under `pseudo`, the text that was not translated (the language names, never translated, are left out). A language run, `--language en` included, turns every language on for that run only, so route R1 adds stills of the **GENERAL** tab and the open language list.

</Details>

## Checks in CI

- **`godot` job:** regenerates the template and fails when the committed one differs.
- **`tools` job:** `selftest`, `glossary`, `potfiles --check` and `check`. It needs no Godot.
- **Headless suites:** `i18n_test` checks the language table, locale lookup and fonts, including the language list's own font chain, and lays out every offered language and pseudo-English in the game (title, credits, changelog, Settings, Pause, touch buttons and every word the USE button shows, the tutorial, the answer rows, the end card, and station names at every **TEXT SIZE**), failing any text that does not fit its room (none is let off: `KNOWN_OVERFLOWS` is empty), and draws every short line of each language in the hint bar and the top card, failing one that takes more than one row beyond English or more than three rows; `settings_test` checks the **LANGUAGE** row and its saved setting, and that the menus' built text (prompts, key names, the Settings note, Pause's hint) follows a language change; `i18n_test` also checks the HUD's key prompts and, in a game, the hint, tutorial, top card and touch button in a test language. For the story it checks that English comes back unchanged, that each speaker's words translate apart from the tag, that the template holds every story line with its marks, and that an old save's answer is quoted in pseudo-English. What it found: [What was checked](/docs/development/evidence/#languages-october-16-2026).
- **Overlap checks in every language:** `text_boxes_languages_1_test` and `text_boxes_languages_2_test` run the station-name, touch layout, top card and tutorial prompt overlap checks of `text_boxes_test` in every offered language and in pseudo-English.
- **One switch for the checks:** the suites and the parity capture change language, or turn pseudo-English on, with `I18n.apply_for_checks`.
- **Every suite runs in English** (`--language en`), whatever your computer's language.

## Spanish

- **Two files:** `es.po` is Latin-American Spanish, the base. `es_ES.po` is Spain's adaptation of it, changed only by the Spain list in `i18n/style/es-ES.md`.
- **Which file a player gets:** Spain's region gets `es_ES`; every other Spanish locale gets `es`.
- **Every line has a note:** a `#. TRANSLATORS:` line says where it shows and how much room it has, and `#. i18n:` marks say who speaks and how the player is addressed.
- **Some words were cut to fit,** such as EMPEZAR for NEW GAME. The list is in `i18n/style/es-419.md`, "Open questions".
- **Review state:** machine translation, not reviewed. See [Credits](/docs/credits/#translations).

## Portuguese, French and German

- **Three files:** `pt_BR.po` (Brazil), `fr.po` and `de.po`, made the same way as Spanish.
- **Portugal** gets `pt_BR`, the one Portuguese file.
- **French spacing:** a no-break space (U+00A0) goes before `; : ! ?` and inside « ».
- **Some words were cut to fit,** such as JOUER for NEW GAME and NUTZEN for USE. The lists are in `i18n/style/pt-BR.md`, `fr.md` and `de.md`, "Open questions", and each cut is noted on its line.
- **Review state:** machine translation, not reviewed. See [Credits](/docs/credits/#translations).

## Polish and Russian

- **Two files:** `pl.po` and `ru.po`, made the same way as Spanish.
- **No one-letter word ends a row:** *a, i, o, u, w, z* and *а, в, и, к, о, с, у, я* are bound to the next word with a no-break space (U+00A0). `check` fails a line that leaves one free.
- **The engineer has no past tense:** both languages show gender in the past tense, so those lines use the present, a noun or an impersonal form.
- **Names stay in their own form,** after a colon or a dash where the sentence would decline them.
- **Russian keeps some words in Latin letters:** names, tools, web addresses and key labels such as Esc. They are listed under `keep` in `i18n/glossary.json`.
- **Some words were cut to fit,** such as DALEJ and ДАЛЕЕ for CONTINUE. The lists and the word choices for reviewers are in `i18n/style/pl.md` and `ru.md`, "Open questions", and each cut is noted on its line.
- **Review state:** machine translation, not reviewed. See [Credits](/docs/credits/#translations).

## Japanese, Korean and Chinese

- **Four files:** `ja.po`, `ko.po` and `zh_Hans.po`, made the same way as Spanish, and `zh_Hant.po`.
- **Traditional Chinese is converted, not translated again:** OpenCC (`s2twp`, Taiwan phrases) turns `zh_Hans.po` into Traditional characters, then each line is checked for Taiwan usage. A line the check changed says so in its note, such as 存取 for access.
- **Which file a player gets:** Taiwan, Hong Kong and Macau get `zh_Hant`; every other Chinese locale gets `zh_Hans`. The two must translate the same lines (the sibling gate).
- **Each turns on only its own font:** the chosen language's Noto Sans subset, with Roboto's line height.
- **Reading speed:** a dialogue box is timed at the language's subtitle speed: 4 characters a second in Japanese, 12 in Korean, 9 in Chinese. Rows run to the column width.
- **The engineer:** no pronoun (彼女, 그녀, 她) and no gendered word stands for the engineer. The name is in Latin letters, as in every language.
- **Korean rows break at spaces:** the text server would break Hangul between any two syllables, so the game puts a two-row box's break at the space that leaves the most even rows, and splits a box that needs split words at its sentences.
- **Korean particles:** a particle such as 은 or 는 depends on the name's last sound, so lines use one that never changes (의, 에게) or end the clause on the name.
- **Words outside the font subsets were reworded,** such as がれき for 瓦礫. The lists and the word choices for reviewers are in `i18n/style/ja.md`, `ko.md`, `zh-Hans.md` and `zh-Hant.md`, "Open questions".
- **Review state:** machine translation, not reviewed. See [Credits](/docs/credits/#translations).

## Exports

**What the Mac and Windows builds carry for each language.** Measured on the test build of commit `670b8ed` (October 19, 2026).

- **Both builds:** the game's pack holds `languages.json`, every offered language's `.po` file, the four CJK font subsets and their picker fonts, and the ICU line-breaking data (`icudt_godot.dat`).
- **Mac:** Godot writes a `<code>.lproj` folder with an `InfoPlist.strings` into `Contents/Resources` for English and for each registered catalog: `de`, `en`, `es`, `es_ES`, `fr`, `ja`, `ko`, `pl`, `pt_BR`, `ru`, `zh_Hans`, `zh_Hant`.
- **What the folders do:** macOS reads them as the app's languages. The Mac App Store builds its language list from them.
- **The name stays WOLF OVERRIDE** in every language: the folders hold no translated name.
- **Windows:** has no language list to declare. Everything rides in the `.exe`'s embedded pack.
- **The check:** `scripts/package_test_build.py` fails a test build whose pack lacks the table or an offered language's catalog, or whose Mac app has other `.lproj` folders than the offered languages.
- **Not checked yet:** how App Store Connect names `es` and `es_ES`, and whether it reads `zh_Hans` and `zh_Hant` with an underscore. That needs a TestFlight build, and none exists.
- **Later, with the phone builds:** Android's `locales_config` and its `values-pt-rBR` folder names, and iOS's own language list.

## Add a language

Each language comes in its own pull request. There is no translation website.

1. Write the catalog `apps/game/i18n/<code>.po` from the template, following the glossary and style guides.
2. Run `i18n_tool.py check`, with `--back` for an independent back-translation.
3. Turn the language on in `languages.json` and register its catalog in `project.godot`; `i18n_test` fails if the offered languages, the files and the registered catalogs differ.
4. Capture the routes with `scripts/parity/run.sh capture --language <code>` and look for overflow.
5. Credit it and add a changelog line, labelled "machine translation" until a native speaker reviews it.
