**What this page is for:** when the game saves, what retry does, and where your files live.

- **One checkpoint file.** There are no save slots. Each save replaces the last one.
- **Saving starts at the first SAFE POINT.** After that, the game also saves on its own.
- **A knockdown costs one step at most.** Your choices are kept.

## When the game saves

| Where | What saves |
| --- | --- |
| Maintenance corridor | Using the green **SAFE POINT** beyond the sealed door (your first save) |
| Records Access | Entering from the safe point, copying the purge-order trace, preserving the mirror timestamp, securing the first copy at the exit |
| Service Junction | Entering the room, blowing the sealed door, bringing down the sentry, leaving through the exit door |

- **You will see Checkpoint saved.** in the hint line for about two seconds (never over a choice). The safe point says it in its own line.
- **A save stores** the room, both characters' positions, puzzle state, the engineer's display name and the remembered choice.

### If a save fails

1. The hint line shows **Save failed. Use a station to try again.**
2. Press interact again, at a station or anywhere in the room. That retries the save.
3. Progress since the last good save is stored once a later save works.

- **The message stays** until you move to another spot or a later save works.
- **If the first safe-point save fails,** the safe point stays unused, so you can use it again.

### Service Junction: what Continue brings back

| Save | Continue restores |
| --- | --- |
| Entering the room | Door sealed, breaker ready to arm, valve turns back to zero |
| Blowing the door | Door down, breaker and valve used, sentry patrolling from the far end, tank hung over the mark |
| Bringing down the sentry | Sentry down under the tank, exit bolt still to pop |
| Leaving through the exit door | Nothing to continue: the slice is finished, and the title offers **PLAY AGAIN** |

## Knockdowns

**Knockdown** means the engineer is knocked to the floor by a hazard. It can happen only in the Service Junction: the relief vent, the door blast, the sentry or the coolant cloud.

1. The screen flashes red and the engineer drops to the floor.
2. Read the line. It names what hit you and how to avoid it.
3. From just under a second (0.9 seconds) after the hit, the hint offers **RETRY**.
4. Press interact (**E**, controller **A**, **TAP RETRY** on touch).
5. The screen fades to black and back to the room's last automatic save.

- **No rush.** The screen waits for **RETRY** and never moves on by itself. Pause works while the card is up.
- **Timing:** control returns about half a second after you press, so about 1.5 seconds after the hit if you press at once.
- **Same every time:** the first knockdown and every repeat use the same timing.
- **No penalty.** You lose only the step you were on. Earlier choices and Records progress are kept.
- **Reduced Motion:** the engineer is shown lying on the floor at once, with the thud and a shorter red wash. See [Accessibility](/docs/accessibility/#reduced-motion).

<Details>
<Summary>What if the save could not be read?</Summary>

- If the last save failed to write, or the file cannot be read, retry still returns you to the start of the step you were on, kept in memory.
- The line after it then reads **Back at the start of this stretch.** instead of **Back at the last checkpoint.**
- A knockdown never writes the save file.
- A blown door stays blown through every reload. The used breaker and valve cannot be used again.

</Details>

## Continue and New Game

| Button | What it does |
| --- | --- |
| **Continue** | Resumes your checkpoint without replaying the opening |
| **New Game** | Starts a fresh run with the opening; the old checkpoint stays until the new run saves over it |
| **PLAY AGAIN** | Shown after you finish the slice, in place of both; works like New Game |

- **In Records Access,** Continue tells you which copy is next or that the exit is open.
- **After the slice,** the note reads **Slice complete. PLAY AGAIN starts a fresh run.**
- **A half-written save:** if the checkpoint is missing or damaged but a complete save was still being written when the game closed, Continue uses that copy.

### Why is Continue greyed out?

Read the note under it:

| Note | Meaning | Fix |
| --- | --- | --- |
| **No checkpoint yet. Saving starts at the first SAFE POINT.** | You have not used a safe point | Play to the safe point and use it |
| **Saved checkpoint could not be read** | The file is damaged | Start a New Game and reach the safe point to replace it |

## Pause and Return to Title

- **Esc** opens Pause during play and the closing scene: **Resume**, **Settings**, **Return to Title**.
- **During the opening,** Pause shows **Skip Opening** instead of Return to Title.
- **Switching away** from the game during play opens Pause. It does not save.
- **Return to Title** warns that unsaved progress is lost. It keeps the last checkpoint.

### Go back to your last checkpoint

1. Open Pause.
2. Choose **Return to Title**.
3. Choose **Continue**.

There are no load or restart hotkeys.

## Where saves live

The game writes `m0-save.json` (the checkpoint) and `settings.cfg` (your settings) here:

- **macOS:** `~/Library/Application Support/Godot/app_userdata/WOLF--OVERRIDE/`
- **Windows:** `%APPDATA%\Godot\app_userdata\WOLF--OVERRIDE\`
- **Linux:** `~/.local/share/godot/app_userdata/WOLF--OVERRIDE/`

<Callout type="warn" title="Deleting the folder deletes your progress">
  Removing this folder removes the checkpoint and your settings. There is no undo.
</Callout>

- **The double dash is normal.** Godot replaces the slashes in the project name with dashes.
- **Safe writes:** a save goes to `m0-save.json.tmp` first and is renamed when complete, so a half-written file never replaces a good checkpoint.
- **Tests don't touch it.** `bun run game:check` uses a temporary folder.
