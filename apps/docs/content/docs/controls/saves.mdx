## When the game saves

- **Safe point.** Use the green **SAFE POINT** beyond the sealed door. This is the first save in a run.
- **Records Access.** Entering Records Access from the safe point, copying the purge-order trace, preserving the mirror timestamp, and securing the exit each save automatically.

A save stores the room, both characters' positions, puzzle state, the engineer's display name, and the remembered choice. There is one checkpoint file, not multiple save slots, and each save replaces it.

If an automatic save fails, the hint line shows **Save failed. Use a station to try again.** until you move to another spot or a later save works. Using a station again retries the save; if entering Records Access did not save, the first station there does. If the first safe-point save fails, the safe point stays unused so you can use it again.

## Continue and New Game

**Continue** on the title screen resumes a valid checkpoint without replaying the opening. In Records Access it tells you which copy is next or that the exit is open. When Continue is unavailable, a note under it says why: **No checkpoint yet** means no safe point has been used, and **Saved checkpoint could not be read** means the file is damaged; reaching the safe point in a new run replaces it. If the checkpoint file is missing or damaged but a complete save was still being written when the game closed, Continue uses that copy.

**New Game** begins a fresh run with the opening. The old checkpoint remains until the fresh run saves over it.

## Pause and Return to Title

During gameplay or the player-paced closing beat, **Esc** opens Pause with **Resume**, **Settings**, and **Return to Title**. During the opening, Pause shows **Skip Opening** in place of Return to Title. Switching away from the game during play also opens Pause; it does not save.

**Return to Title** warns that unsaved progress is lost and keeps the last checkpoint. To restore that checkpoint during play, choose Return to Title, then **Continue**.

## Where saves live

The game writes `m0-save.json` (the checkpoint) and `settings.cfg` to Godot's user data folder for the project:

| Platform | Folder |
| --- | --- |
| macOS | `~/Library/Application Support/Godot/app_userdata/WOLF--OVERRIDE/` |
| Windows | `%APPDATA%\Godot\app_userdata\WOLF--OVERRIDE\` |
| Linux | `~/.local/share/godot/app_userdata/WOLF--OVERRIDE/` |

Godot replaces the slashes in the project name with dashes. A save is written to `m0-save.json.tmp` first and renamed when complete, so a half-written file never replaces a good checkpoint. Deleting the folder removes the checkpoint and your settings. `bun run game:check` uses a temporary folder and never touches these files.
