title: Input guide
description: Default keyboard, controller, and touch inputs for the current source build.
---

You control the engineer. WOLF is an independent companion. The in-game prompts follow your selected keyboard or controller bindings.

## Keyboard and mouse

| Input | Action |
| --- | --- |
| A / D or left / right arrow | Move |
| E | Interact; advance the opening or chapter closing beat |
| 1 / 2 or click a response | Choose the displayed answer |
| Esc | Pause or resume; during the opening, Pause offers Skip Opening |
| I | Cycle provisional engineer display names |

## Controller

| Default input | Action |
| --- | --- |
| Left stick or D-pad left / right | Move |
| A | Interact or advance |
| X / Y | Choose answer 1 / 2 |
| Start | Pause or resume; during the opening, Pause offers Skip Opening |

These are generic controller labels. Equivalent buttons may have different labels on your controller. Menus support focus navigation and confirmation: the selected item shows a cyan outline inside its border, and Pause menu buttons and the Settings **BACK**, FPS limit and resolution controls also thicken their border and fill. Closing Settings from the title returns the selection to **SETTINGS**. A complete physical-controller playtest remains outstanding.

## Touch

On iOS and Android builds, hold the left/right arrows to move, tap **USE** to interact, and tap the displayed answer. **PAUSE** opens Resume, Settings, and Return to Title (Skip Opening during the opening). On Android, the system Back gesture backs out of menus and pauses play; it only closes the game from the title screen. Leaving the app during play pauses the game. Menus opened by touch show no selection outline; the first arrow key or controller press selects a menu item without activating it.

Touch controls appear in mobile builds. There is no public mobile download yet. A simulator launch has been checked; complete touch gestures and physical devices remain unverified.

Need to change a binding? Open [Settings](/docs/controls/settings/). For checkpoint behavior, see [Saving and resuming](/docs/controls/saves/).
