M10 Settings, phone and tablet

What this page is for: judge the full-screen settings on a phone and a tablet, touch first.

How to use it

  1. Set Device to iPhone, Android or iPad in the strip.
  2. Tap a tab. Its page shows. LB and RB do the same with a pad.
  3. Tap FRAME RATE on DISPLAY to open its list.
  4. Set Input to pad. The controller rows, the ring and the footer prompts appear.
  5. Set Phone controls to "tap to walk" to see the other TOUCH SCHEME. Neither is decided yet.
  6. Set Speaker to see the dialogue preview with a name tab or a placeholder portrait.
  7. Android: add cutout= and edge= (canvas px) to see the unmeasured bands.

What each tab shows

  • DISPLAY: phone rows only. FRAME RATE offers 30, 60 or 120 FPS.
  • AUDIO: one slider per sound.
  • CONTROLS: TOUCH SCHEME, CONTROL SIZE, SWAP SIDES and HAPTICS. With a pad, the controller rows come first.
  • ACCESSIBILITY: too many rows for one screen, so the page scrolls. Text never shrinks. The dialogue preview sits above DIALOGUE BACKING.
  • GENERAL: DEVICE PROFILE fixes a wrong guess in one change. RESET is hold to confirm.
  • The review stills are URL states of this frame, listed in data/m10.json.

Layout (proposal)

  • The tabs stand in a column on the left. A phone is short, so a tab row would cost a row of settings.
  • BACK sits top right, in the title row. That leaves room for five or six rows.
  • With a pad, LB and RB sit on one line above the rail, not in the footer. This breaks 3.1 step 7 on purpose: a footer TABS prompt runs over the caption in the title row. On touch the line is gone.
  • Rows stay 44 pt tall or more. Long pages scroll; the last row fades when more lies below.
  • On the iPad every touch page fits. Only the longer page with a pad connected scrolls.
  • Switches draw half a row tall. The whole row is the tap target, so the tap stays 44 pt.

Not on a phone

  • WINDOW MODE, WINDOW SIZE, MONITOR and V-SYNC: the OS owns the window.
  • MUTE WHEN UNFOCUSED and PAUSE WHEN UNFOCUSED: a phone always pauses and mutes.
  • CLICK / TAP TO INTERACT: TOUCH SCHEME covers it.
  • QUIT: never on iOS. Android Back quits from the bare title.

Shared code (November 11)

  • Built: D-pad focus scrolls the page, so the ring stays on the screen.
  • Built: the preview box stays put on touch; the USE clearance applies only to in-play boxes.
  • Still open: at TEXT SIZE 200% the tab rail and long choices run past the bottom of the screen.
  • Still open: a tap hides the controller rows again. There is no "pad connected" flag yet, so they follow the last input.
