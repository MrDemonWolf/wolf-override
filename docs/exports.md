The title's New Game and Continue buttons are the only tap-oriented controls observed so far; no mobile touch layout or export is configured. ## Icon preparation (deferred)

Use one editable 1024-square design with separate background and transparent wolf artwork. Keep an opaque, flattened square PNG for conventional icons. The existing [provisional SVG mark](../apps/game/assets/logo-mark.svg) is source material, and each derived asset needs an entry in the populated [asset register](../apps/game/assets/manifest.json); its brand-rights review remains open.

- **Mac and iOS:** Apple's [Icon Composer](https://developer.apple.com/icon-composer/) imports SVG or PNG layers and saves a layered `.icon`; it requires macOS 26.4 or later. Godot 4.7 has a macOS [`application/liquid_glass_icon`](https://docs.godotengine.org/en/4.7/classes/class_editorexportplatformmacos.html) field, usable when exporting from macOS with Xcode 26+, plus a conventional `application/icon` fallback for older macOS. Godot's [iOS exporter](https://docs.godotengine.org/en/4.7/classes/class_editorexportplatformios.html) exposes image icon slots but no `.icon` field. Later, add the Composer file to the exported Xcode project using [Apple's instructions](https://developer.apple.com/documentation/xcode/creating-your-app-icon-using-icon-composer), and verify a repeatable setup after Godot re-exports.
- **Windows:** Use the opaque square PNG in the export preset; [Godot converts PNG, WebP or SVG to ICO](https://docs.godotengine.org/en/4.7/tutorials/export/changing_application_icon_for_windows.html) for the executable. A separate `.ico` is needed if setting `application/config/windows_native_icon` for the running taskbar icon.
- **Android:** [`@mrdemonwolf/iconwolf-mcp` 0.4.0](https://www.npmjs.com/package/%40mrdemonwolf/iconwolf-mcp) can draft adaptive foreground, background and monochrome PNGs, which map to [Godot's Android icon fields](https://docs.godotengine.org/en/4.7/classes/class_editorexportplatformandroid.html). Inspection of the published IconWolf source indicates `.icon` input is flattened before foreground generation and monochrome is made by grayscale conversion. Use transparent wolf artwork as input and inspect the results against [Android's layer and safe-zone guidance](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive); draw a separate monochrome silhouette if the generated one fails.

No Icon Composer, IconWolf, export template or icon preset was installed or configured in this task.

## Candidate app identifiers

Use `com.mrdemonwolf.wolfoverride` provisionally for the macOS bundle ID and Android application ID. It fits the [Godot 4.7 macOS reverse-DNS rule](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_macos.html) and the [Godot 4.7 Android `package/unique_name` rule](https://docs.godotengine.org/en/4.7/classes/class_editorexportplatformandroid.html). Set it in the macOS export preset's **Application → Bundle Identifier** and the Android export preset's **Package → Unique Name** when those presets are actually created; the eventual App Store Connect and Google Play records must match the exported IDs. The matching iOS bundle ID is a candidate only if Mac and iOS will share Apple's [universal purchase](https://developer.apple.com/help/app-store-connect/create-an-app-record/add-platforms); independent Apple store records need distinct bundle IDs. If chosen, set the iOS ID in its [Godot Application export options](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_ios.html). This app ID is separate from the proposed `wolfoverride://` URL scheme.

Confirm identifier availability and the Apple purchase model before registration. [Apple cannot change a bundle ID after a build is uploaded](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information), and [Android treats a changed application ID as a different app after publication](https://developer.android.com/build/configure-app-module). No app ID or URL scheme has been registered or configured.

## Future distribution options

These are plans, not release commitments. Windows is intended to be free. A separate direct-download Mac build could be offered through a [Homebrew cask](https://docs.brew.sh/Acceptable-Casks); its price is open. A cask needs a current developer-published binary that passes macOS Gatekeeper checks. [Sparkle](https://sparkle-project.org/documentation/) could update that direct Mac build after there is a signed release and update feed. The proposed Mac App Store price is **US $4.99**, subject to confirmation in App Store Connect; [Mac App Store updates must go through Apple](https://developer.apple.com/app-store/review/guidelines/), so that build must not use Sparkle. Paid distribution requires Apple's [Paid Apps Agreement](https://developer.apple.com/help/app-store-connect/manage-app-pricing/set-a-price).

The chosen public-code license is GPL-3.0-or-later. [GNU permits charging for copies and permits recipients to redistribute them](https://www.gnu.org/licenses/gpl-faq.en.html#DoesTheGPLAllowMoney). Apple's [standard EULA](https://www.apple.com/legal/internet-services/itunes/dev/stdeula/) restricts redistribution and modification, though Apple allows a [custom EULA](https://developer.apple.com/help/app-store-connect/manage-app-information/provide-a-custom-license-agreement). Whether the intended GPL code, separate game assets, store terms and distribution method are compatible needs legal review before any App Store submission; a custom EULA alone is not a confirmed solution. Keep asset rights and provenance in the asset register.

iOS/iPadOS would use Apple's App Store and Android would use Google Play, later. Decide iOS pricing before creating Apple app records: a shared Mac/iOS record becomes a [universal purchase](https://developer.apple.com/help/app-store-connect/create-an-app-record/add-platforms), while separate prices require separate records. At Android release, reconcile [Google Play's current API 36 target requirement](https://developer.android.com/google/play/requirements/target-sdk) with the [Godot 4.7 Android setup instructions](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_android.html), which still list SDK Platform 35. Verify all platform requirements again at export time.
